# OCR・ローカル・クラウド処理の連動

## 実行の責務

| 担当 | 入力と処理 | 保存・出力 |
| --- | --- | --- |
| 独立OCRジョブ | 保存済み添付から原文を取り出し、保存済みページをローカル解析する | OCR原資料、ローカル解析、集約した状態記録 |
| クラウドバックログ | ローカル結果がある対象ページを、既存の承認範囲・予算・枠で追加解析する | 会計証拠、確定応答、クラウド解析 |
| 原資料の読取り | 現在の患者権限・資料・ページ・必要な解析の完了を照合する | 出典付きの患者コンテキスト、紹介状・PCAの表示 |
| 人による誤り報告 | 現行の原資料・ページ・解析を指定し、理由と承認を記録する | 訂正依頼のreceiptと、その後の再解析 |

OCRは収集ジョブから呼び出さず、既存スケジューラーの毎分ジョブが担当します。
保存済み資料だけが対象で、このジョブのためにMCSサーバーへアクセスしません。
新しい常駐サービスは追加しません。standaloneでは単一host、Hermesでは既存のcron登録が所有します。
導入・更新コードはこのジョブを配置しますが、コードの変更だけで稼働環境へ適用されたことにはなりません。

## 完了・保留・復旧

| 状態・イベント | 次の処理 | 許可しない扱い |
| --- | --- | --- |
| 現行OCR原文を保存 | ローカル解析を待つ | OCR成功だけで臨床解析完了にしない |
| ローカル解析が完了 | クラウドが必要なら追加解析を待つ | 必要なクラウド解析をローカル結果で代用しない |
| クラウド応答を受信 | journalへ保存し、会計を確定してから解析結果を採用する | 保存失敗を未送信と推測しない |
| 確定済みの同じ応答が残る | 原資料・範囲・要求・会計の証拠を検証し、現在の解析条件で再検証する | 古いローカル保存IDだけを理由に同じ要求を再送しない |
| 送信結果不明・破棄済み・証拠不足 | クラウドは保留し、証拠を保持する | 成功・未送信への推測変換や自動再送をしない |
| 会計復旧記録が破損・復旧不能 | クラウド送信を閉じ、ローカル解析は継続して監視へ記録する | 別患者を含むローカル処理まで一律に止めない |
| OCR固有のクラウド処理が例外 | エラーを記録し、次回の抽出ターンは通常チャットへ譲る | 同じOCR処理だけを繰り返して通常抽出を止めない |
| 原資料の変更・撤回、患者権限の失効 | 古い結果を現行資料の採用から除外する | 旧結果の再利用で権限を回復させない |

モデル・承認範囲・送信内容が違う要求を、同じ応答で満たしたことにはしません。
課金記録と原資料の保存証拠は変更せず、新しい解析の採用条件を別に検証します。
異なる添付・ページは、両者の原資料と所有証拠を検証した場合だけ別の処理対象として扱います。
帰属を確定できない旧記録を、この区別のために対象外へ落としません。
アーカイブ・閲覧禁止・権限失効・患者情報が欠けた資料は、原資料を読む共通入口で拒否します。
OCR実行中に設定をOFFにした場合や、実行設定を変えた場合も、保存前に照合して新しい結果を採用しません。

## 独立ジョブと資源制御

専用ジョブは単一ロックで重複実行を防ぎます。1回の総予算は900秒、
ローカル解析1回は最大120秒、OCR1回は従来の設定上限までです。
ローカル処理を優先しながら、原画像のOCRも順番に進めます。予算内なら複数ページ・複数添付を処理します。
保留・無進捗・失敗になった段階は、その回の中では繰り返さず、もう一方の段階を進めます。
両方が停止した場合や予算・更新境界に達した場合は終了し、次回へ引き継ぎます。

ローカル解析は背景slotと共通のGPU順番待ちを使い、呼出元のリアルタイムslotを借りません。
背景処理の指定は呼出し範囲に閉じ、他の実行や環境変数へ残しません。
OCRエンジンも起動前に既存のメモリー確認を使います。不足・確認不能なら試行回数を消費せず保留します。
共有の書込みロックは短い保存・公開時に使い、OCRやモデル応答の待ち時間全体には保持しません。

この設計は処理量の固定制限と段階間の停止依存を解消するものです。実機での速度・メモリー使用量や、
一定件数を処理できることを保証する数値は含みません。

## 表示・報告・監視

対応外の添付は除外件数へ分けます。未取得・不明・失敗・未完了を対応外へ移しません。
紹介状・PCAでは文字のある全ページに必要な解析が揃った資料だけを表示し、上限・保留を明示します。
PCAの値は未確認の候補であり、投与量や終了時刻を計算しません。

薬剤詳細からの報告に加え、本文表示から解析済みOCRページを開けます。
薬剤の抽出が0件でもページを確認して報告できます。対象はその本文のmanifest・患者・親投稿または返信に束縛し、
ページ送りのボタンも同じ条件を維持します。
ページ送りは添付ID・ページの境界を使い、先頭から過去ページを読み直しません。
件数・時間の上限で未点検が残る場合は続きの境界を返し、抽出0件でも後方へ進めます。表示前に閲覧条件を確認し、報告の確定時にも現行資料を再確認します。
ユーザー入力で別の患者・資料・ページを指定する経路は追加しません。

クラウド会計の復旧待ちは、ローカル処理の進捗と分けて監視に残します。
メモリーによる保留は処理失敗に数えません。必要な証拠を確認できない状態は、正常な0件として扱いません。

## OCRモデルの版固定

導入処理とOCR実行は、`mcs/extract/ocr_model_contract.py` の同じモデル版を使います。
検出・文字認識・レイアウト・表構造の4モデルをコミットIDで固定し、実行時はその版のローカルキャッシュだけを読みます。
モデル版を変更した更新では、OCRを導入済みの場合だけインストーラーの再実行を要求します。
重みと実行ファイルを確認してから、導入完了の印を保存します。

モデル版は保存結果の処理条件にも含めます。旧版の結果と履歴は残しますが、現行の原資料としては採用しません。
原本が残る添付は新しい版で再処理します。原本を削減済みの添付は再処理できないため、原本を再取得する必要があります。
旧版のOCRから得たローカル・クラウド結果や患者コンテキストを、新しい版の結果として扱いません。
