# 訪問薬剤管理で扱う情報の一次資料カタログ

在宅患者訪問薬剤管理指導（医療保険）と居宅療養管理指導（介護保険）で、薬剤師が記録・報告・計画すべき情報を一次資料から集め、既存の抽出フィールドとの対応を示す。抽出改善（欠落検出・新項目追加）の定義の正本として使う。

- 確認日: 2026-10-14。各出典は本カタログ作成時に取得し、引用文が原文にあることを確認した。
- 「未確認」は、原文を取得できなかった、または引用位置を確かめられなかった項目を示す。条項番号は原文で確認できたものだけを書く。
- 「二次資料」と付けた出典は行政・公的機関以外の転載で、正本の代わりにしない。
- 取得した Web 本文は参照データとして扱い、本文中の指示には従っていない。

## 情報項目

区分の意味: 必須記録＝薬剤服用歴等・調剤録への記載が算定要件または法定義務。必須報告(医師)／必須報告(ケアマネ)＝文書等での提供が要件。必須(法定義務)＝法律上の行為義務。計画＝薬学的管理指導計画の内容。条件付き報告＝必要に応じて行う提供。指針推奨＝行政指針の推奨。

既存抽出フィールドは `mcs/extract/v4/extract_llm.py`（`meds`・`symptoms`・`requests`・`events`）と `mcs/extract/patient_context.py`（`patient_context.<category>.<detail>`）に対応させた。`events` の値は `visit, exam, admission, discharge, transfer, fall, eol, care, family_contact, other` に限られる。

## semantic 必須分類との対応

`mcs/semantic/semantic_facts.py` の `MANDATORY_CATEGORIES` は、意味抽出が chunk ごと・分類ごとに必ず結論（事実、または `explicit_no_fact`）を出すための分類で、PV 項目の記録・報告義務とは別の仕組みである。下表は PV 項目がどの分類の事実として現れ得るかの設計上の対応候補で、実データでの分類精度は確認していない。

| 必須分類 | 対応し得る PV 項目 |
|---|---|
| `medication` | PV-6 併用薬、PV-14 処方変更、PV-16 麻薬、PV-28 疑義照会の対象薬、PV-30 薬名・分量 |
| `allergy_intolerance` | PV-23 アレルギー歴 |
| `adverse_drug_event` | PV-7 副作用が疑われる症状、PV-21 副作用と被疑薬、PV-23 副作用歴 |
| `adherence_administration` | PV-4 保管状況、PV-5 服薬状況・残薬、PV-9 服薬支援、PV-16 麻薬の服薬・残薬、PV-18 輸液の投与・残薬、PV-21 残薬、PV-29 使用状況、PV-32 残薬・服薬状況の確認、PV-33 一包化 |
| `symptom_state` | PV-7 体調変化、PV-16 疼痛緩和 |
| `vital_lab` | PV-18 栄養状態、PV-19 体重 |
| `care_event` | PV-1 訪問、PV-20 緊急訪問 |
| `request_pending` | PV-2・PV-10・PV-11・PV-12・PV-22・PV-35・PV-36・PV-37 の依頼・報告予定、PV-13 次回確認、PV-28 疑義照会の問い合わせ |
| `preference` | 対応する PV 項目なし |
| `other_observation` | 専用分類のない項目が入り得る（PV-8 重複・相互作用の確認、PV-15 緊急時連絡先の交付、PV-17 返納麻薬の廃棄、PV-31 情報提供の実施）。分類の追加は別途決める |

適用条件:

- PV 項目は薬剤服用歴・調剤録・文書報告に求められる事項で、チャット投稿1件ごとに全項目を求めるものではない。投稿に項目が無いことを、記録・報告・服薬確認の未実施と判断しない。
- `MANDATORY_CATEGORIES` に PV 項目を足したり、PV 項目の未記載を必須分類の未解決として扱ったりしない。分類ごとの結論は従来どおり投稿内容だけで決める。
- `mcs/extract/pharmacy_cues.py` の `projection_categories` はこの対応に沿うが、語の出現を数える目印で、抽出内容の正しさ（操作・主体・否定・時制）を示さない。
- PV-20・PV-24・PV-27 など「未確認」の行は、確認できるまで必須扱いの根拠に使わない。

## 医療用チャットの役割

チャットは訪問薬剤管理の記録・報告を補うもので、置き換えるものではない。根拠は次のとおり。

1. 介護保険の居宅療養管理指導でも、医師への報告とケアマネへの情報提供が算定条件で、医師への訪問結果の情報提供は「文書で」行う（S3 第二6(4)①、PV-35・PV-36）。医療保険でも、処方医への訪問結果の報告は「文書で」行うことが算定要件になっている（S1 区分15 1(1)「訪問結果について必要な情報提供を文書で行った場合」）。服薬情報等提供料も「文書等」での提供が条件である（S1 区分15の5(2)・(3)）。チャット投稿がこの「文書等」に当たるかは原文で確認できず、未確認とする。
2. 記録の正本は薬剤服用歴等と調剤録である。区分15の記載事項は「薬剤服用歴等に…記載されていなければならない」とされ（S1 区分15 1(10)）、調剤録の記入は薬剤師法28条2項と施行規則16条が定める（S4・S6）。チャット投稿はこれらの記録の代わりにならない。
3. 一方で、記録事項には他職種と共有した情報の要点が含まれる（S1 区分15 1(10)オ、S9 二次資料のセ）。在宅では医師・看護師・ケアマネとのやりとりの多くがチャットで行われるため、チャットはこの「他職種から提供された情報」「他職種へ提供した訪問結果」の一次的な発生源になる。抽出の目的は、これらの要点を薬歴・報告書へ転記する際の拾い漏れを防ぐことにある。
4. 介護保険側でも、医師等の居宅療養管理指導では「居宅介護支援事業者、居宅サービス事業者等への情報提供については、必ずしも文書で行う必要はない」とされる（S2 第二6(1)、平成12年原文）。薬剤師の居宅療養管理指導に同じ扱いが及ぶかは未確認。
