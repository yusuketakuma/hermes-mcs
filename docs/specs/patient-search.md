# 患者の原資料検索

患者の管理カードにある「👤 患者情報」「🔎 この患者を検索」から、同じ患者の別スレッドを含めて記録を探せる。検索は保存済み原文を読むだけで、LLMの処理完了を待たない。ローカルLLM・クラウドLLMを呼ばず、患者コンテキストの生成回数も消費しない。

## 検索対象と条件

対象は本文を取得済みの投稿と、現在の添付ファイルに対応すると確認できたOCR本文である。削除された投稿、閲覧権限を失った患者、差し替え前の添付OCRは対象外とする。添付OCRが設定で無効か利用を確認できない場合は、その範囲を検索していないことを表示する。OCR本文の検索に添付のローカルLLM解析は必要ない。

検索語は空白で区切り、すべてを含む原資料を検索する。全角・半角、大文字・小文字、本文の空白の差は既存の正規化で吸収する。6語目以降を捨てず、入力は500文字までとする。既存の限定的な質問文の検索語変換は維持する。質問への回答を新しく生成する機能ではない。

| 条件 | 例 | 対象 |
|---|---|---|
| 資料 | `資料:投稿`、`資料:添付`、`資料:全て` | 投稿本文、添付OCR、両方 |
| 分類 | `分類:服薬管理`、`分類:生活環境` | 現在の原資料に結び付く解析結果で分類を確認できた記録 |
| 開始 | `開始:2026-11-01` | JSTの指定日以降の投稿 |
| 終了 | `終了:2026-11-07` | JSTの指定日の末尾までの投稿 |

`カレンダー 分類:服薬管理 開始:2026-11-01`のように、検索語と条件を組み合わせる。不正な条件や重複した条件は無視せず、入力を確認する案内を返す。分類には既存の患者コンテキスト分類名・別名・識別子を使える。分類を付けると解析結果が必要になるため、解析前の原文も探す場合は分類を付けない。

日付の条件は投稿日時に対する条件で、本文中の発症日・測定日などを推定しない。添付の日時・職種も添付元の投稿を示し、文書の作成日や著者の職種とは区別する。本人・家族などの対象者、否定、用量、日付は原文の引用と原資料表示に残す。

## 続きの検索と原資料の表示

1回の結果は最大5件で、新しい投稿から順に表示する。探索は64件の投稿候補と64件の原資料を上限とし、原資料の間で1秒の探索予算を確認する。1回のSQLや原資料検証を途中で打ち切る実時間保証ではない。結果数または探索予算の上限で止まると「続きを検索」を表示し、その先を未検索として扱う。調べた範囲に一致がなくても、未検索範囲があれば全体の0件とは表示しない。

続きの位置は患者・検索語・条件に結び付け、同じ投稿の残りの添付ページにも進める。各ページはその時点の読取スナップショットで検証する。ページ間に新しく届いた投稿は、最初から検索し直すと対象になる。全件数を求めるための全履歴走査や、原文を複製する検索用の永続索引は作らない。

結果の「原資料を開く」は、検索した投稿または添付OCRページの本文を表示する。長文は4000文字ずつ「前の範囲」「次の範囲」で読める。毎回、患者の閲覧範囲と原資料の識別子・更新状態を照合する。変更・削除・権限喪失を検知した場合は古い本文を出さず、再検索を案内する。

MCSへのリンクには実装済みの患者ルームURLを使う。未確認の投稿単位URLを生成しない。OCRの未完了・確認不能は検索結果と分け、履歴の取得範囲も併記する。記録が見つからないことを、症状や対応がなかったこととは扱わない。

## 非公開表示と操作の識別

検索結果と原資料はSlack・Discordでは操作者向けの非公開表示、LINE WORKSでは本人とのDMに返す。Slackのスレッド内表示は、そのカードの本文配信が確認できる場合に使う。Discordの返信スレッドの入口も、同じカードに属する配信済み本文の証跡を必要とする。

他スレッドの原資料を開く操作には、操作者・患者・カード・操作元に結び付いた読取専用の参照を発行する。カード本文の表示範囲やスタンプ操作用の参照は流用しない。表示内容は既存の一時的な応答経路だけへ渡し、操作結果の永続記録へ本文を保存しない。

LINE WORKSの入力は操作者ごとに1件とする。入力画面の準備中も要求IDを保持し、別の患者の画面を重ねて開かない。「取消」後に届いた旧要求の画面は表示せず、別の患者の入力を上書きしない。同じ患者の操作を明示的に開き直すことはできる。

## CLIと実装

`mcs_view.py patient_context --project <患者ID> --view search --query '<検索語と条件>'`も同じ検索を使う。続きは応答の`next_cursor`をJSON文字列として`--cursor`へ渡す。結果の`source_ref`は原資料の識別用で、単独ではチャットの操作権限を与えない。

読取は`mcs/views/patient_search.py`、既存の分類・証拠の採用は`mcs_queries.source_patient_context`と`attachment_context_items`、原資料の識別は`inference_dependency_loss`と`original_source_keys`を利用する。通知側は`notify_actions._patient_search`から既存の本人向け表示へ接続する。既読化、スタンプ送信、患者コンテキスト作成、検索結果の共有送信は検索の副作用に含めない。

更新後のHermesではgateway、LINE WORKSでは独立アダプターの再起動が必要となる。既存カードの操作ラベルは通常のカード更新後に反映する。実サービス上の表示確認は合成テストの成功と区別して扱う。
