# LINE WORKSの画面例ギャラリー

READMEのLINE WORKS折りたたみで使う、架空の名前・投稿を使った説明図2枚。
実画面のキャプチャではなく、実患者・実投稿・匿名化データは使用しない。
PNGはREADME表示用、SVGは編集用のソース。配置・書体・絵文字は版や設定で異なる。
画像内のボタンは操作できない。

## ソースとの対応

| 画面 | 根拠 |
|---|---|
| `01-delivery` | `adapters/lineworks/cards.py`（`確認する`・`担当する`・`タスク作成`・`MCSで開く`・`その他の操作`のFlexメッセージ）、`mcs/notify/notify_render.py`の`display_text`（区画を`────────────`で区切ったカード本文）・`_message_post`（表示形式3は見出し・要約・スタンプのヘッダと原文を別投稿に分離）、`adapters/lineworks/delivery.py`（同じトークルームへカード・ヘッダ・原文・添付を連続投稿し、変更したヘッダだけを追加） |
| `02-task-confirm` | `adapters/lineworks/actions.py`（`_more`による「その他の操作」の1:1メニュー。項目はカードのボタン行の順で、未完了タスクがあれば`タスク一覧`が先頭、本人の1:1トークへの項目別入力・確認・確定）、`adapters/common/text.py`（入力ラベル・確認本文・結果の文言） |

ボタンの種類とCallbackは[公式Flex仕様](https://developers.worksmobile.com/jp/docs/bot-send-flex)・[Flexボタン](https://developers.worksmobile.com/jp/docs/bot-send-flex-button)とも照合。
Flexの`altText`には患者・発信者・所属・時間・要約を送る。本文は図の表示を保持し、
実際のプッシュ表示は端末・アプリの通知設定に依存する。
架空の元投稿と抽出参照があるカードを例にしている。ボタンは状態・設定で変わり、
本文の長さや操作数によって追加投稿に分割される。
この2枚はスタンプ送信の操作者・MCSアカウントを設定していない例で、読取り表示だけを示す。
両方を設定して送信が有効な場合は、共有カードに1回押しのスタンプ列が追加される。この設定例は[Slackの`03-actions`](../slack-gallery/README.md)を参照する。
添付は保存・通知のみで、画像内容の解析は示していない。
新規カードの表示形式3では、要約・スタンプをヘッダ投稿へまとめ、原文と分ける。
右側の要約は配置説明用の抜粋で、実際は公開可能な要約の複数行を保持する。
図のスタンプ更新ではヘッダだけを追加し、「本文は変更なし」と案内する。
カードと操作の意味が変わらない場合は、カード・ボタンを再利用する。
送信済みの内容は編集・削除されず、過去の要約やスタンプ表示も残る。
既存の表示形式1・2は更新だけで変換せず、実際の内容変更時には原文を含む再投稿が残る。
要約の初回待機は最大120秒（緊急表示は待たない）。1件の投稿の更新には
初回分割数に加えて最大3投稿の枠があり、最後は上限の案内に使う。

1:1図の左側は「その他の操作」で届くメニューと、「タスク作成」の入力の抜粋。
担当者はスタッフ一覧を使わず手入力する例で、理由の入力後の確認画面を右側に示す。
「受け付けました。」と、処理結果取得後の「反映しました。」を区別する。
確認済みの表示はタスク完了を意味しない。カード置換に成功した場合は
古いボタンと開いている確認を無効にする。区画だけの更新ではボタンの期限を
延ばさず再利用し、原文世代・期限・権限の検証を維持する。
共有トークの参加者には原文・要約・添付・更新内容が見え、
1:1へ操作を分けても共有済みの内容は非公開にならない。詳細は[導入・接続手順](../../guides/LINEWORKS.md)。

## 生成と確認

```bash
python3 scripts/development/generate_lineworks_gallery.py --png
python3 scripts/development/generate_lineworks_gallery.py --check
```

PNGの生成には日本語フォントとInkscape、またはmacOS標準Quick Lookを使用する。
新しいPython依存やLINE WORKS接続は不要。macOSの正方形サムネイルに合わせた
1100×1100のSVGを1650×1650で出力する。
SVGとPNGを一緒に更新し、PNGを開いて文字切れ・重なり・表示の意味を確認する。
`assets.json`は両形式のSHA256を記録し、`--check`でソースとの同期、PNGの
サイズ・CRC・画像データ・組のhashを検証する。CIのrelease-notes workflowも確認する。
