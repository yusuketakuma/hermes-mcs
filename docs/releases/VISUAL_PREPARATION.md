# リリース図の準備と公開時の配置

2026-10-05、v1.0.0〜v1.0.13の文章をコミット履歴と対象タグへ照合して改善した。図は同じ確認済み情報から作る動作・情報の流れの説明図で、実画面のスクリーンショットではない。旧版のSlack等を同条件で再現できていないため、画面比較を推測して作らない。

## 今回の保存先と制約

画像・SVG原稿・生成スクリプト・版ごとの根拠とaltは、ローカルの作業成果物フォルダー（完了報告に記載）に準備する。画像公開・アップロード・既存公開タグの変更は今回の範囲外なので、画像ファイルをpushしない。Release本文にはローカルパス、未公開URL、未確認のMermaidを埋め込まず、比較表と文章を掲載する。

## 公開が許可された時の手順

1. ローカルの `docs/releases/vX.Y.Z/` のSVG・PNGと根拠記録を、リポジトリの同名配置へコピーする。原稿から再生成し、PNGを開いて文字欠け・重なりを確認する。390px相当の表示でも主要ラベルを読む。掲載する図は原則各版1〜3点にする。
2. 画像の追加を別commitとして公開する。既存のリリースtagへ追加・付け替えせず、画像公開commitの固定SHAを記録する。
3. その固定SHAのPNGを指すGitHub rawの絶対URLを使う。変更され続けるmainのURLを過去版の画像参照にしない。URLは公開後に読者と同じアクセス条件で取得し、PNG内容・版・ハッシュを照合する。
4. CHANGELOGの該当変更の説明直後へ、版ごとのaltを持つ画像参照と、変更点・メリットの1〜2文を入れる。補足・技術図は末尾の折りたたみへ置く。図だけに設定・注意を置かない。README要約を生成し、同じCHANGELOGからReleaseへexport・同期する。
5. GitHub Releasesの実画面で画像の取得と表示を確認し、スマートフォン相当の幅も確認する。URL到達、Markdown変換、実画面表示は別の結果として記録する。

今回、公開画像URLの到達・GitHub Releasesでの画像表示・旧新版スクリーンショットの条件一致は未確認／対象外。画像がなくても本文で変更と必要操作を理解できるようにする。
