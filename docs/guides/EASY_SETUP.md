# はじめての導入・更新・困ったときの操作

Macの「ターミナル」で、画面の質問に番号を入力して進みます。選択に迷ったら「推奨」を選んでください。Enterだけで進む場合は、画面に表示された選択になります。
施設のログイン情報・通知先・操作を許可する人は、推奨値では決められません。不明なときは施設の管理担当者に確認してください。

## 1. 始める前に用意するもの

- macOS 13以降のMac。普段使うユーザーでログインします。
- 空き容量約12GBとインターネット接続。
- 利用権限のあるMCSアカウントのログインIDとパスワード。
- 通知を使う場合は、施設が使用を認めたSlack・Discord・LINE WORKSの通知先と接続設定。これから選ぶ場合の推奨はSlackです。

パスワードや接続用の秘密情報は、端末の専用入力欄に入力します。入力中に文字が表示されないのは正常です。チャットや問い合わせメールに貼らないでください。
通知を有効にすると、患者名・投稿本文・対象の添付が指定した通知先に届きます。施設の利用許可と通知先を確認してから設定します。

## 2. 初めてインストールする

すでに導入済みなら「4. 更新する」へ進んでください。既存の設定フォルダを削除してやり直す必要はありません。
今回の初回受入候補はmacOS・Apple silicon・Slackのstandaloneです。この候補で導入する場合は、手順5で`2) MCS 単独で使う`を選びます。正式対応・実機受入の完了を意味せず、既存環境の方式や画面の既定値は変えません。

1. MacのSpotlight検索（⌘＋スペース）で「ターミナル」を検索して開きます。
2. 初めて使うMacでは、次のコマンドを入力し、表示される画面に沿って開発用の基本ツールを入れます。すでに入っていると表示された場合は次へ進みます。

   ```sh
   xcode-select --install
   ```

3. [Homebrewの公式ページ](https://brew.sh/ja/)の手順でHomebrewを入れます。施設管理のMacで操作を制限されている場合は管理担当者に依頼します。
4. 次の3行を順に実行します。取得したフォルダは運用中も使うので、移動・削除しないでください。

   ```sh
   git clone https://github.com/yusuketakuma/hermes-mcs.git
   cd hermes-mcs
   ./install.sh
   ```

5. 画面でSlack・Discordとの連携方式を選びます。今回の初回受入候補は `2) MCS 単独で使う` です。[独立実行ガイド](STANDALONE.md)でSlackアプリの準備も確認します。Hermesとの連携を選ぶ場合は `1) Hermes Agent と連携（標準）` です。Enterの既定は従来どおり1です。LINE WORKSを含め、通知先のアプリは後の初期設定で選びます。表示された導入内容を確認し、ダウンロード中は完了表示まで待ってください。
6. 導入後の案内で初期設定へ進みます。後で行う場合は、次のコマンドで再開できます。

   ```sh
   ~/.local/bin/mcs setup
   ```

「ソフトの準備が完了しました」は必要なソフトが入ったという意味です。通知先・ブラウザー・接続確認が済むまでは利用開始の確認が残ります。
導入前に問題の有無だけ確認したい場合は `./install.sh --preflight`、変更予定だけ確認したい場合は `./install.sh --dry-run` を使います。
連携方式をコマンドで指定する場合は `./install.sh --mode hermes` または `./install.sh --mode standalone` を使います。選択画面は初回の対話導入で表示され、導入済みの環境では設定済みの方式を保持します。

## 3. 初期設定を進める

最初は「必要な項目だけ」のコースを選んでください。質問しない項目は設定済みの値を保持し、未設定ならその版の既定値を使います。通知スレッドと通知のまとめ方は、必要な場合に質問します。後で同じコマンドを開き、全項目を確認できます。

| 質問の内容 | 入力・確認すること |
|---|---|
| MCSのログインID | 普段MCSへログインするときのID。分からない場合は管理担当者へ確認 |
| 通知先 | 施設が認めたチャンネル・トークルーム。個人用や公開の場所を誤って選ばない |
| 通知アプリのID・接続情報 | 作成したアプリの設定画面から取得。名前だけでは設定できない項目がある |
| 操作を許可する人・対象プロジェクト | 実際に閲覧・操作してよい人とMCSの対象。分からない値を適当に入力しない |
| 収集・通知の範囲 | 画面の説明を確認し、必要な範囲を選択 |
| 医薬品辞書 | 同梱の公式医薬品マスターで薬剤名を照合するか（推奨: はい）。画面に表示される利用条件を確認した日・確認した人・照合の承認を入力します。承認しない場合は参照のみで照合しません。すでに辞書を設定済みなら質問は出ません |
| パスワード・接続用の秘密情報 | 端末の非表示入力欄へ直接入力 |

設定入力後に、通知先・送る情報・認証情報の保存先を確認します。保存する場合だけ「はい」または1を選んでください。ここで空欄・拒否・中止を選ぶと、今回の設定・辞書・認証情報は保存しません。辞書の作成とパスワードの保存は、この確認の後に進みます。保存後の接続設定で中断した場合は、保存済みの設定を保持して再開できます。

設定を保存した後、JevとAnthropicのAPIキーを入力するか選べます。キーを利用する設定では、投稿や患者の文脈が各サービスへ送られ、費用が発生することがあります。対象範囲と利用条件を確認してください。入力は表示されず、選んだキーだけをこのMCSの `.env` に保存します。既存のキーを残す場合は「現在のまま」を選びます。後から端末で `mcs setup api-keys` を実行して設定することもできます。

接続情報の取得は[Slack・Discordの設定](INSTALLATION.md)、[LINE WORKSの設定](LINEWORKS.md)を参照してください。通知サービスのアプリ作成権限がない場合は、管理担当者の作業が必要です。

設定後の診断で残った項目を順に解消します。ブラウザーは[専用Chromeとセッション確認](INSTALLATION.md#初回の専用chromeとセッション確認両モード共通)に従い、専用プロファイル準備→本人ログイン→Chromeの稼働→MCSセッション→初回収集を分けて確認します。初回の自動ログインにブラウザー準備を任せず、他にログイン可能なOSアカウントがある場合は管理者に利用条件を確認します。LINE WORKSは接続ガイドの認証・受信URL・常駐設定も完了してから再診断します。

次のすべてを確認したら利用を開始します。

- 設定と診断が正常に終了している。
- 利用する通知先・対象・操作を許可する人が正しい。
- MCSへ接続でき、想定した通知先で受信・表示・必要な操作を確認できる。

ソフトの導入成功と、実際の接続・通知確認は別です。診断で未確認と表示された項目を、正常と読み替えないでください。

初期設定の最後に、任意機能（CSDC: 状態監視・遠隔支援）の案内を表示するかを選べます。この版の既定は「省略」です。選ぶのは案内の表示だけで、登録や送信は始まりません。後から変える場合は端末で `mcs setup features`（PATH未設定なら `~/.local/bin/mcs setup features`）を実行します。

## 4. 更新する

v1.0.25以降を導入済みのMacで次を実行します。

```sh
~/.local/bin/mcs update
```

画面に沿って更新先と更新計画を確認します。推奨の正式版を選べます。最後の実行確認では、内容を確認してから更新を選びます。Enterだけで更新を開始することはありません。
更新中は収集や通知が一時停止することがあります。終了結果と残る確認事項を読んでから画面を閉じてください。

詳細な再導入や独立実行モードの操作が必要と表示された場合は、[更新手順](UPGRADE_AGENT.md)を管理担当者と確認します。案内が更新を拒否した場合は、手作業で上書きせず理由を解消します。
v1.0.24以前にはこの対話入口がありません。
初回の更新は管理担当者と[更新手順](UPGRADE_AGENT.md)に従って進めてください。

## 5. 途中で止まった・動かなくなった

まず、読取り専用の診断をします。

```sh
~/.local/bin/mcs doctor
```

更新が途中で止まったときは、復旧の案内を開きます。

```sh
~/.local/bin/mcs recover
```

最初に状態を確認します。理由が分からなければ、推奨の「診断・相談」を選んで止めて構いません。実行を選ぶ前に、表示された復旧対象と注意事項を確認します。
復旧用プログラムが未導入・古い場合や、更新途中ではない不具合では、表示された手順に沿って管理担当者へ相談してください。
実行環境の移行が保留された場合は、通常の復旧を繰り返さず管理担当者と[更新手順](UPGRADE_AGENT.md)を確認してください。
`mcs`自体を起動できない場合は、本体とは別に保存されている `~/.mcs-recovery/mcs_recover.py` を使います。管理担当者が `~/Library/LaunchAgents/org.mcs.recovery.plist` に登録された独立Pythonを確認し、そのPythonでこのファイルを起動します。対話版対応を確認してから `--interactive` を指定してください。古い版はこの引数を無視して復旧を始めるため、確認せず実行しないでください。

復旧の案内は、途中で止まった更新を扱います。紛失したMacの復元、壊れたデータの任意上書き、通知の一括再送は行いません。バックアップからデータを戻す操作には、[バックアップと復元の手順](BACKUP.md)にある個別の確認・承認が必要です。

| 表示・状況 | 次にすること |
|---|---|
| 番号の入力間違い | 画面にある番号を入れ直す |
| 必須情報が分からない | 中止して管理担当者に確認。同じコマンドで再開できる |
| ダウンロード失敗・空き容量不足 | 通信・空き容量を確認後、同じ導入コマンドを再実行 |
| 診断が失敗・承認待ち | 表示された理由を確認。設定やデータを削除して回避しない |
| コマンドが見つからない | 上記の `~/.local/bin/mcs` という省略していないパスを使う |

Ctrl+Cで中断できます。処理段階によっては設定や導入の一部が保存されています。更新・復旧を中断した場合は診断で状態を確認してから再開します。
問い合わせ時は、実行した操作とエラーの種類を伝えてください。画面全体や設定ファイルには秘密情報・患者情報が含まれることがあるため、そのまま送らないでください。
