# はじめての導入・更新・困ったときの操作

Macの「ターミナル」で、画面の質問に番号を入力して進みます。選択に迷ったら「推奨」を選んでください。Enterだけで進む場合は、画面に表示された選択になります。
施設のログイン情報・通知先・操作を許可する人は、推奨値では決められません。不明なときは施設の管理担当者に確認してください。

## 1. 始める前に用意するもの

- macOS 13以降のMac。普段使うユーザーでログインします。
- 空き容量約12GBとインターネット接続。
- 利用権限のあるMCSアカウントのログインIDとパスワード。
- 通知を使う場合は、施設が使用を認めたSlack・Discord・LINE WORKSの通知先と接続設定。これから選ぶ場合の推奨はSlackです。Slackを新しく用意する場合は、workspaceでアプリを作成できる権限と、Bot token・App-level token・操作を許可する人のユーザーIDが必要です。投稿先は既存チャンネルのIDを使うか、初期設定で非公開の`mcs`・`mcslog`を自動作成できます。Socket Modeと必要な権限は[Slackの接続準備](STANDALONE.md#slackとdiscordの接続準備)を確認してください。

パスワードや接続用の秘密情報は、端末の専用入力欄に入力します。入力中に文字が表示されないのは正常です。チャットや問い合わせメールに貼らないでください。
通知を有効にすると、患者名・投稿本文・対象の添付が指定した通知先に届きます。施設の利用許可と通知先を確認してから設定します。

## 2. 初めてインストールする

すでに導入済みなら「4. 更新する」へ進んでください。既存の設定フォルダを削除してやり直す必要はありません。
新規導入の推奨はmacOS・Apple silicon・Slackのstandaloneです。以下ではこの方式を明示します。既存環境では設定済みの方式を引き継ぎます。AIへ任せる場合は、[READMEの依頼文](../../README.md#quickstart)を使えます。Codex・Claude Code・Devinなどへ依頼するときは、リポジトリURL（https://github.com/yusuketakuma/hermes-mcs）を読み込ませ、初期設定と正常動作の確認が終わるまで同じセッションを維持してください。Mac上で操作する権限がないエージェントは導入を実行せず、本人の端末で行う手順を案内します。

1. MacのSpotlight検索（⌘＋スペース）で「ターミナル」を検索して開きます。
2. 初めて使うMacでは、次のコマンドを入力し、表示される画面に沿って開発用の基本ツールを入れます。インストーラの完了を確認してから次へ進みます。すでに入っていると表示された場合は次へ進みます。

   ```sh
   xcode-select --install
   ```

3. [Homebrewの公式ページ](https://brew.sh/ja/)の手順でHomebrewを入れます。施設管理のMacで操作を制限されている場合は管理担当者に依頼します。インストールの最後に表示される「Next steps」も実行します。Apple siliconのMacでは通常、次の2行です。実行後は`brew --version`が表示されることを確認してください（ターミナルを開き直しても構いません）。

   ```sh
   echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
   eval "$(/opt/homebrew/bin/brew shellenv)"
   ```

4. 次の4行を順に実行します。取得したフォルダは運用中も使うので、移動・削除しないでください。`--preflight`は何も変更せず、不足しているものだけを表示します。

   ```sh
   git clone https://github.com/yusuketakuma/hermes-mcs.git ~/hermes-mcs
   cd ~/hermes-mcs
   sh scripts/mcs install --mode standalone --preflight
   sh scripts/mcs install --mode standalone
   ```

5. 上のコマンドではMCS単独の方式を選択済みです。表示された依存ソフトと導入段階を確認し、完了まで待ちます。通知先のアプリは後の初期設定で選び、Slackは[独立実行ガイド](STANDALONE.md#slackとdiscordの接続準備)の準備も確認します。Hermes連携を希望する場合は`--mode hermes`を指定します。方式を決めずに選択画面を開く場合は`--mode standalone`を省きます。新規導入の推奨とEnterの既定はstandalone（MCS単独）です。既存環境は現在の方式を維持します。
6. 導入後の案内で初期設定へ進みます。後で行う場合は、次のコマンドで再開できます。

   ```sh
   ~/.local/bin/mcs setup
   ```

「ソフトの準備が完了しました」は必要なソフトが入ったという意味です。通知先・ブラウザー・接続確認が済むまでは利用開始の確認が残ります。
導入前に問題の有無だけ確認したい場合は `./install.sh --preflight`、変更予定だけ確認したい場合は `./install.sh --dry-run` を使います。
連携方式をコマンドで指定する場合は `./install.sh --mode hermes` または `./install.sh --mode standalone` を使います。選択画面は初回の対話導入で表示され、導入済みの環境では設定済みの方式を保持します。

## 3. 初期設定を進める

最初は「必要な項目だけ」のコースを選んでください。Hermes連携かMCS単独かは導入時に選んだ方式を引き継ぎ、このコースでは質問しません。通知の形式を選んでから送り先を入力し、選んだ接続先で必要な質問だけへ進みます。質問しない段階は表示せず、総数は現在の選択に応じて変わります。質問しない項目は設定済みの値を保持し、未設定ならその版の既定値を使います。通知スレッドと通知のまとめ方は、必要な場合に質問します。後で同じコマンドを開き、全項目を確認できます。

| 質問の内容 | 入力・確認すること |
|---|---|
| MCSのログインID | 普段MCSへログインするときのID。分からない場合は管理担当者へ確認 |
| 通知の形式 | ボタン付きのSlack・Discord・LINE WORKS、または文章のみを選択。文章のみでも通知は送る |
| 通知先 | 施設が認めたチャンネル・トークルーム。個人用や公開の場所を誤って選ばない |
| 通知アプリのID・接続情報 | 作成したアプリの設定画面から取得。名前だけでは設定できない項目がある |
| 操作を許可する人・対象プロジェクト | 実際に閲覧・操作してよい人とMCSの対象。分からない値を適当に入力しない |
| 収集・通知の範囲 | 画面の説明を確認し、必要な範囲を選択 |
| 医薬品辞書 | 同梱の公式医薬品マスターで薬剤名を照合するか（推奨: はい）。画面に表示される利用条件を確認した日・確認した人・照合の承認を入力します。承認しない場合は参照のみで照合しません。すでに辞書を設定済みなら質問は出ません |
| パスワード・接続用の秘密情報 | 端末の非表示入力欄へ直接入力 |

設定入力後に、通知先・送る情報・認証情報の保存先を確認します。保存する場合だけ「はい」または1を選んでください。ここで空欄・拒否・中止を選ぶと、今回の設定・辞書・認証情報は保存しません。辞書の作成とパスワードの保存は、この確認の後に進みます。保存後の接続設定で中断した場合は、保存済みの設定を保持して再開できます。

設定を保存した後、Jev・Anthropic・OpenAIのAPIキーを入力するか選べます。キーを利用する設定では、投稿や患者の文脈が各サービスへ送られ、費用が発生することがあります。対象範囲と利用条件を確認してください。キーを入れなくても収集・通知は進められますが、そのサービスを使う追加解析は利用できません。入力は表示されず、選んだキーだけをこのMCSの `.env` に保存します。既存のキーを残す場合は「現在のまま」を選びます。後から端末で `mcs setup api-keys` を実行して設定することもできます。

接続情報の取得は[Slack・Discordの設定](INSTALLATION.md)、[LINE WORKSの設定](LINEWORKS.md)を参照してください。通知サービスのアプリ作成権限がない場合は、管理担当者の作業が必要です。

設定後の診断で残った項目を順に解消します。初期設定が正常に終わると、続けて専用ChromeでMCSへログインするかを尋ねます。後で行う場合や、認証切れの通知が届いた場合は次を実行します。

```sh
~/.local/bin/mcs setup browser
```

収集専用のChromeが開いたら、MCSのログイン画面にIDとパスワードを入力してログインし、端末に戻ってEnterを押します。「ログインした状態を確認しました」と表示されれば完了です。このChromeは閉じずに使い続けます。他にログインできるOSアカウントがあるMacでは、安全のためChromeを開かずに止まるので、管理者に利用条件を確認します（[詳しい説明](INSTALLATION.md#初回の専用chromeとセッション確認両モード共通)）。LINE WORKSのカード・操作を使う場合は、接続ガイドの認証・Callback・常駐設定も完了してから再診断します。文章だけの通知では接続設定と診断を確認します。

ログインと接続確認のあとは、次のコマンドで動作確認を繰り返せます。連続して正常なら終了し、問題があればAIエージェントへ渡せる修正依頼を`~/.mcs/data/postinstall-watch/agent-repair-brief.md`へ保存します。

```sh
~/.local/bin/mcs setup postinstall
```

常駐して使うMacでは、次の運用条件も確認します。収集・通知・ローカルAI・復旧監視は、導入したユーザーがログインしている間だけ動きます。停電・macOS更新・不意の再起動のあとは、そのユーザーがログインするまで再開しません。Mac Studioを施設で常時稼働させる場合は、管理担当者と次を決めてください。

**管理者と決めること**

- 再起動後に誰がログインするか。自動ログインはFileVaultと併用できず、画面ロックや物理アクセスの管理が必要です。自動ログインを使わない場合は、停電・更新後にログインする運用が必要です。
- システム設定でコンピューターのスリープを止め、停電後の自動起動を使うか。変更には管理者権限が必要な場合があります。
- バックアップの保存先・暗号化鍵・復元訓練の担当。設定の編集だけでは定期実行が始まらないため、[バックアップと復元の手順](BACKUP.md)で明示の登録と確認をします。

**自分で確認すること** — 次のすべてを確認したら利用を開始します。

- `~/.local/bin/mcs doctor`で動作を妨げる問題がなく、未確認の項目を正常と読み替えていない。
- `cd ~/hermes-mcs && ~/.mcs/venv/bin/python3 -m mcs_standalone status`で独立hostが稼働している。
- 利用する通知先・対象・操作を許可する人が正しい。
- 初回の収集が終わり、`mcs doctor`や状態画面で患者・メッセージ数を確認できる。
- 再起動後のログイン、スリープ、停電後の再開方法を運用担当者と確認した。
- バックアップを使うか決め、使う場合は[バックアップと復元の手順](BACKUP.md)の登録・鍵保管・復元訓練を確認した。
- MCSへ接続でき、想定した通知先で受信・表示・必要な操作を確認できる。

ソフトの導入成功と、実際の接続・通知確認は別です。診断で未確認と表示された項目を、正常と読み替えないでください。

初期設定の最後に、任意機能（CSDC: 状態監視・遠隔支援）の案内を表示するかを選べます。既定は「省略」です。選ぶのは案内の表示だけで、登録や送信は始まりません。後から変える場合は端末で `mcs setup features`（PATH未設定なら `~/.local/bin/mcs setup features`）を実行します。

## 4. 更新する

対応する更新プログラムを導入済みのstandalone、またはv1.0.25以降のHermes連携のMacで次を実行します。standaloneの旧版は、この案内を読むだけでは新しい更新経路に対応しません。

```sh
~/.local/bin/mcs update
```

画面に沿って公開版と更新計画を確認します。必要な再導入は確認できた以前の導入設定を引き継ぎます。最後の実行確認では、内容を確認してから更新を選びます。Enterだけで更新を開始することはありません。計画だけを見る場合は`~/.local/bin/mcs update plan`を使います。取得済みタグだけを対象にし、適用は行いません。
更新中は収集や通知が一時停止することがあります。終了結果と残る確認事項を読んでから画面を閉じてください。
終了後は`~/.local/bin/mcs doctor`で未検査項目と残る確認を読み、次に`~/.local/bin/mcs doctor --probe services`で明示した常駐処理を追加診断します。最後に通知先で応答を確認します。実際の収集再開は別に確認し、未確認を正常とは扱わないでください。

導入済みのupdaterが未対応、記録や設定が不一致、復旧が保留中などで止まった場合は、表示された理由を保持して管理担当者へ確認します。standaloneの旧版・外部から取り出した更新ツール・未公開候補は、この新しい経路では適用しません。内部引数の追加や新しいclone、手作業の上書きで続行しないでください。[standaloneの具体的な操作](STANDALONE.md#更新復旧)と[対応する導入済みupdaterの条件](UPGRADE_AGENT.md#1-a-対応する導入済みstandaloneの対話更新)を確認します。
Hermes連携のv1.0.24以前にはこの対話入口がないため、[更新手順](UPGRADE_AGENT.md)を管理担当者と確認してください。

## 5. 途中で止まった・動かなくなった

まず、読取り専用の診断をします。

```sh
~/.local/bin/mcs doctor
```

更新が途中で止まったときは、復旧の案内を開きます。

```sh
~/.local/bin/mcs recover
```

最初に状態を確認します。理由が分からなければ、推奨の「診断・相談」を選んで止めて構いません。実行を選ぶ前に、表示された復旧対象と注意事項を確認します。
復旧用プログラムが未導入・古い場合や、更新途中ではない不具合では、表示された手順に沿って管理担当者へ相談してください。
実行環境の移行が保留された場合は、通常の復旧を繰り返さず管理担当者と[更新手順](UPGRADE_AGENT.md)を確認してください。
`mcs`自体を起動できない場合は、本体とは別に保存されている `~/.mcs-recovery/mcs_recover.py` を使います。管理担当者が `~/Library/LaunchAgents/org.mcs.recovery.plist` に登録された独立Pythonを確認し、そのPythonでこのファイルを起動します。対話版対応を確認してから `--interactive` を指定してください。古い版はこの引数を無視して復旧を始めるため、確認せず実行しないでください。

復旧の案内は、途中で止まった更新を扱います。紛失したMacの復元、壊れたデータの任意上書き、通知の一括再送は行いません。バックアップからデータを戻す操作には、[バックアップと復元の手順](BACKUP.md)にある個別の確認・承認が必要です。

| 表示・状況 | 次にすること |
|---|---|
| 番号の入力間違い | 画面にある番号を入れ直す |
| 必須情報が分からない | 中止して管理担当者に確認。同じコマンドで再開できる |
| ダウンロード失敗・空き容量不足 | 通信・空き容量を確認後、同じ方式・オプションの導入コマンドを再実行。新しくcloneしない |
| 「認証切れ」の通知が届いた・ログインを確認できない | `~/.local/bin/mcs setup browser`で専用Chromeを開き、MCSへログインし直す |
| ソフトの準備後に初期設定を中止 | `~/.local/bin/mcs setup`で再開。保存済みの設定・認証情報を削除せず、未完の項目を確認 |
| 診断が失敗・承認待ち | 表示された理由を確認。設定やデータを削除して回避しない |
| コマンドが見つからない | 上記の `~/.local/bin/mcs` という省略していないパスを使う |

Ctrl+Cで中断できます。処理段階によっては設定や導入の一部が保存されています。更新・復旧を中断した場合は診断で状態を確認してから再開します。
問い合わせ時は、実行した操作とエラーの種類を伝えてください。画面全体や設定ファイルには秘密情報・患者情報が含まれることがあるため、そのまま送らないでください。
