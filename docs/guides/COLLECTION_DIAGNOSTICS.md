# 収集エラーと未取得本文を確認する

監視警報が `stage_errors` や `collection_incomplete` を示したときは、エラーの種類と、まだ取得できていない記録の件数を確認します。診断自体は収集・再送・既読化・修復を実行しません。

導入時に選択したMCS用Pythonの絶対パスを`PY`に指定してください。macOS標準の`python3`とは区別します（[導入ガイド](INSTALLATION.md)）。

```sh
PY=/absolute/path/to/mcs-python
"$PY" mcs/ops/mcs_setup.py doctor --probe data
"$PY" mcs/ops/mcs_setup.py doctor --probe data --json
```

`--probe data` がない場合、この診断は状態ファイルもDBも読みません。指定した場合は保存済みの `data/health.json` にある `collection_diagnostics` を読み、直接DBを再走査しません。古い状態ファイルは「古い記録」、項目のない旧版・不正な記録・観測上限超過は「確認できません」とし、正常や0件に置き換えません。

## 表示する内容

- エラー: 下の表の固定分類と件数、分類ごとの対処。件数は直近の1回の収集に記録されたエラー数で、累積発生数や患者数ではありません。256件を超える場合、総数と先頭256件の内訳を区別します。1.1.0 より前の版が書いた記録は、従来の9分類（ログイン・認証、取得制限、時間切れ、通信、応答形式、保存、取得未完了、操作の取込み、その他・原因未分類）で表示します。
- 取得未完了: アクティブ患者の `fetch_state=incomplete` の件数と固定の理由。これは投稿数とは別です。
- 未取得の親本文: 上の患者に属する、保存済みの `unknown`・`snippet` の親投稿数と、`first_seen`（その投稿を初めて保存した時刻）からの最長経過時間。返信・取得済み本文・削除済み本文・アーカイブ患者は含みません。

経過時間は「連続して取得に失敗した時間」や「投稿からの時間」ではありません。初回観測時刻が欠ける・不正・未来の場合は時刻不明として数えます。いったん取得済みになった投稿は、この件数から外れます。患者の理由が親本文未取得でも、DBに該当する未取得本文が保存されていなければ、その投稿の経過時間は計測できません。

## エラーの分類と対処

| 区分 | 何が起きたか | 自動で再試行 | 利用者の対処 |
|---|---|---|---|
| ログイン・認証 | MCSへのログインが切れたか、認証に失敗しました | いいえ | MCSに手動でログインし直す（docs/guides/INSTALLATION.md の session_expired） |
| 閲覧権限 | MCSが閲覧を拒否しました（権限がない投稿・患者があります） | いいえ | MCSの画面で対象の閲覧権限を確認 |
| ブラウザ接続の準備 | MCSに接続するためのブラウザを準備できませんでした | はい | 次回の収集で再試行されます。続く場合はChromeの起動とログイン状態を確認 |
| 取得制限 | MCSの取得制限にかかりました | はい | 対処不要。間隔をあけて自動で再試行します |
| 時間切れ | 処理が制限時間内に終わりませんでした | はい | 次回の収集で続きから再試行されます。続く場合はネットワークとllama-serverの負荷を確認 |
| 時間内に終わらず先送り | 時間内に終わらなかった処理を次回に回しました（異常ではありません） | はい | 対処不要。次回以降に実行されます |
| 通信 | MCSとの通信に失敗しました | はい | 次回の収集で再試行されます。続く場合はネットワーク接続を確認 |
| MCS側の応答異常 | MCSが異常な応答（エラー番号付き）を返しました | はい | 次回の収集で再試行されます。続く場合はMCSの画面が開けるか確認 |
| 応答形式 | MCSの応答が想定と違う形式でした（MCS側の仕様変更の可能性） | いいえ | 続く場合は開発元へ連絡（python3 mcs/ops/mcs_setup.py doctor の結果を添える） |
| 保存 | 取得した内容をこのMacに保存できませんでした | いいえ | ディスクの空き容量と data フォルダの書込み権限を確認 |
| 取得未完了 | 一部の投稿・返信を取り切れませんでした | はい | 次回以降に続きを取得します。続く場合はMCSの画面で対象が開けるか確認 |
| 添付の取得 | 添付ファイルを取得できませんでした | はい | 次回の収集で再試行されます。続く場合はMCSの画面で添付が開けるか確認 |
| 補助情報の取得 | 職員一覧・自分の情報など補助的な情報を取得できませんでした | はい | 次回の収集で再試行されます。投稿の収集は続いています |
| 操作の取込み | チャットからの操作・更新の指示を取り込めませんでした | いいえ | 操作をやり直す。続く場合は data/run.log の cmd を確認 |
| 設定 | 設定に誤りがあり、一部の機能を使えません | いいえ | python3 mcs/ops/mcs_setup.py check で設定を確認 |
| 収集後の処理 | 要約・薬剤照合・集約などの収集後の処理が失敗しました（収集は完了しています） | はい | 次回の収集で再実行されます。続く場合は data/run.log を確認 |
| 実行基盤 | 収集の実行そのものに問題がありました（記録・ロック・異常終了など） | いいえ | python3 mcs/ops/mcs_setup.py check を実行。続く場合は data/run.log を確認 |
| その他・原因未分類 | 分類できないエラーがありました | いいえ | 続く場合は data/run.log を確認し、python3 mcs/ops/mcs_setup.py doctor の結果を開発元へ |

いずれも患者名・投稿本文・例外の原文は表示しません。表にないコードは「その他・原因未分類」に入ります。

## 通知のタイミング

収集の一部のエラー・制限時間の超過・取得未完了・通知の待ちのように自然に回復しやすい異常は、同じ異常が3回続けて観測された時点で通知します（収集は通常10分ごとなので、初回からおよそ20分後）。通知には観測した回数と初回からの経過時間を添えます。収集の失敗、状態の記録の停止・破損、ログイン切れ、空き容量不足、保存データの整合性、ローカルLLMの停止など、それ以外の異常は従来どおりすぐ通知します。回数を記録できない場合は、通知を抑えずに出します。

## 観測の範囲

定期処理では、既存の0.25秒の読取り予算内で、患者・親投稿それぞれ最大1024行を確認します。上限やSQLエラーで完走できない場合、取得未完了の件数全体を不明にします。借用したDB接続のtransaction・busy timeout・SQLite制限は元に戻します。診断用のDB書込みやschema変更はありません。

監視警報は既存の異常条件・重複抑制と上の通知のタイミングに従い、現在の記録を示す警報にだけこの内訳を添えます。古い記録の理由を現在の原因とは扱いません。原因を特定できないエラーは「その他・原因未分類」のまま残します。患者名・投稿本文・認証情報・生の例外詳細を新しい内訳へ含めません。

取得できない状態が続くときは、MCSの画面と閲覧権限、ネットワーク、ログイン状態、保存先の空き容量を原因に応じて確認してください。本文を取得できない投稿は既読にしません。ログ全体をチャットへ貼り付けず、調査に必要な固定コードと件数を共有してください。

## サポートへ共有する診断

次のコマンドで、設定値・患者件数・パス・プロセスIDを除いた共有用JSONを表示できます。

```sh
"$PY" mcs/ops/mcs_setup.py doctor --share
"$PY" mcs/ops/mcs_setup.py doctor --share --probe data
```

表示した内容を確認し、必要なときだけコピーして共有してください。自動送信やクリップボードへの書込みは行いません。`--share`自体は追加のprobeを実行せず、既存の`--probe`指定を維持します。`--probe data`で観測した取得未完了は状態のみとし、患者・投稿の件数や投稿時刻は共有用JSONに含めません。収集の観測時刻はUnix秒の`collection.observed_at`で残し、確認できない場合は`null`にします。エラー数は固定分類の診断件数で、患者数ではありません。

`--json`だけの通常診断はローカルでの調査用です。共有用は`--share`を指定してください。CSDCへの診断送信・遠隔操作は別の同意と受入を必要とします。
