# hermes-mcs 運用管理規程（ひな形）

このひな形は、厚生労働省「医療情報システムの安全管理に関するガイドライン 第7.0版」と
「医療機関・薬局におけるサイバーセキュリティ対策チェックリスト（令和8年度版）」の項目に沿って、
hermes-mcs を使う施設が自施設の規程を作るための素案です。法的助言ではありません。
`【 】` を施設の内容に置き換え、施設の個人情報保護規程・就業規則と矛盾しないか確認してから制定してください。

---

## 第1章 総則

**第1条（目的）** この規程は、【施設名】（以下「当施設」）が、多職種連携サービス MCS の記録を
hermes-mcs（以下「本システム」）で保存・整理・通知するにあたり、患者・利用者の情報を安全に扱うために
必要な事項を定める。

**第2条（対象）** 本システムを導入した端末、通知先（【Slack/Discord/LINE WORKS のワークスペース名】）、
連携する外部サービス、及びこれらを利用する職員に適用する。

**第3条（利用目的）** 本システムの利用目的は、在宅療養を支える多職種間の連絡を確認漏れなく受け取り、
担当・引継ぎを記録することに限る。本システムは疾病の診断・治療・予防に用いない。

## 第2章 体制

**第4条（責任者）** 医療情報システム安全管理責任者（以下「責任者」）を【役職・氏名】とする。
責任者は本規程の運用、利用者の許可、外部送信の確認、記録の点検、事故時の対応を統括する。

**第5条（台帳）** 責任者は次を台帳に記載し、変更のたびに更新する。
1. 本システムを置く端末（機種・シリアル・設置場所・OS版・FileVault の有効化）
2. 通知先のワークスペース・チャンネルと参加者
3. 連携する外部サービス（送信するもの・所在国・契約・保存条件）。
   `docs/guides/COMPLIANCE.md` 3章の表を基にする
4. 遠隔保守の有無と委託先

**第6条（委託先の管理）** 本システムの保守を委託する場合、責任分界（`COMPLIANCE.md` 2章）、
作業の事前申請と事後報告、作業記録の提出、守秘義務、契約終了時のデータ返却・消去を契約で定める。

## 第3章 利用者とアクセス

**第7条（利用者の許可）** 本システムの `/mcs` 操作と通知チャンネルは、責任者が許可した職員に限る。
許可は職種・担当業務に必要な範囲とし、患者範囲（`project_ids`）とチャンネルを分けて最小にする。
許可・変更・取消は【様式】に記録する。

**第8条（退職・異動）** 退職・異動・休職の際は、当日中に許可リスト（`allowed_user_ids`）と
通知チャンネルの参加者から外す。責任者は【毎月】、不要なアカウントがないか確認する。

**第9条（認証）** 端末のログインと通知サービスでは二要素認証を使う。二要素認証までの間、
パスワードは13桁以上とし、使い回しを禁止する。定期的な変更は求めない。
画面ロックを【5分】以内に設定する。

**第10条（端末）** 端末は【施錠できる場所】に置き、FileVault を有効にする。USB記憶装置の接続、
不要なソフトウェア・共有機能を制限する。OS と本システムは提供元の更新を【1か月以内】に適用する。
時刻は「日付と時刻を自動的に設定」で標準時刻に合わせる。

## 第4章 外部への送信

**第11条（通知先）** 通知先には患者名・本文・要約・添付が送られる。通知先は当施設が管理するチャンネルに限り、
個人のアカウントや一般公開の場に転送しない。

**第12条（外部AI）** Anthropic・OpenAI・TypeSafe Jev 等の外部AIへの送信は、責任者が次を確認し、
`mcs_compliance.py acknowledge` で記録した後に限る。
1. 入力が学習に使われず、保存期間と削除が契約で定められていること
2. 外国にある第三者への提供の根拠（本人の同意、または契約による体制整備）
3. 第14条の周知

**第13条（MCS の規約）** 本システムの利用について MCS 運営会社の許諾を【書面・日付】で確認し、規約の改定時は再確認する。

**第14条（患者への周知）** 利用目的、通知先・外部サービスへの送信、問合せ窓口を【掲示・ウェブサイト・説明書】で周知し、
周知の日付・方法・内容を記録する。

## 第5章 記録の点検

**第15条（アクセスログ）** 責任者は【毎月第1営業日】に次を実行し、結果を【点検記録】に残す。

```bash
python3 mcs/ops/mcs_compliance.py access-log verify --checkpoint 【前回の件数】:【前回のhead】
python3 mcs/ops/mcs_compliance.py access-log review --days 31
```

`verify` が表示する `records`（件数）と `head` は点検記録に書き、次回の照合に使う。

`many_patients`・`denied`・`off_hours` の印がある利用者は、業務上の理由を確認する。
`verify` が失敗した場合は第18条の事故として扱う。

**第16条（業務日誌）** 端末上で直接データを参照・出力した場合（`mcs_view.py`、`brain_export.py`、
データベースの直接参照等）は、日時・操作者・目的・対象を業務日誌に記録する。

**第17条（記録の保存）** アクセスログ、点検記録、業務日誌、外部送信の確認記録は【5年】保存する。

## 第6章 事故対応

**第18条（報告）** 端末の紛失・盗難、誤送信、不正アクセスの疑い、アクセスログの改ざん検知を知った職員は、
直ちに責任者へ報告する。連絡体制は次のとおりとする。

| 区分 | 連絡先 | 電話・メール |
|---|---|---|
| 責任者 | 【】 | 【】 |
| 本システムの提供者・保守委託先 | 【】 | 【】 |
| 通知サービスの管理者 | 【】 | 【】 |
| 厚生労働省（医療機関等のサイバー攻撃の相談窓口） | 【最新の窓口を記載】 | 【】 |
| 警察（サイバー犯罪相談窓口） | 【】 | 【】 |

**第19条（初動）** 責任者は、被害拡大を防ぐため、必要に応じて本システムの常駐サービスの停止、通知チャンネルの参加者の確認、外部AIの `mode=off` を行う。

**第20条（法令上の報告）** 要配慮個人情報の漏えい等（おそれを含む）は、個人情報保護法第26条により、
個人情報保護委員会への報告（速報はおおむね3〜5日以内、確報は30日以内）と本人への通知を要する。
責任者は期限内に対応する。

## 第7章 事業継続（BCP）

**第21条（重要情報と代替手段）** 本システムが止まっても MCS 本体で連絡を続けられることを前提とし、
本システムは補助の記録とする。停止時は MCS の画面で未読・依頼を確認する。

**第22条（バックアップ）** 日次バックアップに加え、暗号化した外部保存（`docs/guides/BACKUP.md`）を
【週1回】作成する。鍵と復元手順は端末と別の場所に保管し、【年1回】復元訓練を行う。

**第23条（サイバー攻撃の想定）** ランサムウェア等で端末が使えない場合、端末をネットワークから切り離し、
新しい端末へ外部保存から復元する。復元後の通知の再開は責任者が判断する。

## 第8章 保存と廃棄

**第24条（保存期間）** 本システムに保存した記録は、【MCS の正本とは別の補助記録として○年】を目安に保存する。
法定の保存義務がある記録（調剤録・診療録・訪問看護記録等）の正本は本システムに置かない。

**第25条（廃棄）** 端末・記録媒体を廃棄・返却する場合は、データを復元できない方法で消去し、
消去の証跡を残す。バックアップと外部保存の複製も消去の対象に含める。
