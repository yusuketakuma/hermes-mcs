# 添付資料の文字起こし（1.1.2向け）

macOSで画像・PDFの文章をローカルで取り出し、投稿本文とは別の原資料として保存します。
診療情報提供書、訪問看護・薬剤管理・居宅療養管理・リハビリ等の報告書、
処方資料、PCAポンプの表示を対象にしています。
Yomitokuは医療専用に追加学習したモデルではありません。文書認識の結果に、
医療文書の項目分類と、ページ・引用位置を保持する処理を組み合わせます。

## 導入と更新

Yomitokuの公開コード・モデルはCC BY-NC-SA 4.0です。個人の非商用研究など、
利用条件に合う用途で導入してください。商用利用は提供元との別契約が必要です。
本機能の導入操作は、商用利用の許諾やモデルの再配布許可にはなりません。

```sh
bash install.sh --with-yomitoku
```

MCSのPythonとは別に、`MCS_ROOT/ocr-venv`へPython 3.13とYomitoku 0.16.0を導入します。
公式ソースの固定commitを使い、必要なモデルは導入時に取得します。
既存のモデルキャッシュは削除しません。選択した導入項目は更新時にも引き継ぎ、
依存や導入手順が変わった場合は再導入が必要になります。

導入しただけではOCRは動きません。実行ファイルの絶対パスを指定して有効にします。
次は標準の導入先を使う例です。`$HOME`は実際のホームディレクトリに置き換えてください。

```sh
python3 mcs/ops/mcs_setup.py init --set 'attachment_ocr={"enabled":true,"executable":"/Users/your-user/.mcs/ocr-venv/bin/yomitoku","timeout_seconds":120}'
```

収集・定期処理が正常終了した後に、取得済み添付を1件まで処理します。
手動では`python3 mcs/ops/mcs_ocr.py --run`を使えます。
OCR中は収集やLLMと共用の書込みロックを保持しません。演算ライブラリは各1スレッドとし、
同時OCRを専用ロックで防ぎます。Yomitoku内部の処理には並列実行があります。実行中の通信と、一時領域外への書込みは禁止します。

## 原文と出典

投稿本文は書き換えません。OCR資料は添付ID、投稿ID、ページ、元ファイルのSHA256、
ページ本文のSHA256、使用エンジンと版を持つ別の保存記録です。
添付の詳細表示にはページ本文と医療項目を、集計表示には状態だけを返します。
添付が変更・撤回された場合や投稿が削除された場合は、古い文字起こしを現行の資料として使いません。
通常の保持期間に従って添付実体だけが削除された場合、保存済みの文章は残し、元ファイルがない状態を区別します。

OCR文は投稿者の発言として扱いません。現在のチャット抽出・患者コンテキストの
引用契約を変更せず、OCR資料の読取りを独立した入口で提供します。
OCR文のクラウド送信、外部export、チャットへの自動全文通知は追加しません。

## 読み取る項目

| 資料 | 整理する内容 |
| --- | --- |
| 診療情報提供書・退院資料 | 傷病名、紹介目的、既往歴、家族歴、現病歴、症状と検査結果、治療経過、処方 |
| 患者背景・療養資料 | アレルギー、生活背景、家族・介護環境、ADL・認知、栄養、医療機器、療養方針・本人の意向 |
| 訪問看護等の報告書 | 報告期間・訪問日時、病状経過、実施した看護・リハビリ、服薬状況、家庭の介護状況、衛生材料、特記事項 |
| 薬剤管理等の報告書 | 記載された薬剤・服薬状況、経過、指導・支援内容、評価を原文の見出し単位で保持 |
| PCAポンプ | 残量、持続流量、ボーラス量、ロックアウト時間、積算量、要求・実施回数、薬液濃度 |

項目は原文の見出しと引用位置を基に分類します。記載のない病名やアレルギーを
「なし」と補いません。「既往歴及び家族歴」のような複合欄は一つの引用として残します。
薬剤の規格を服用量として転記せず、薬剤名を似た名称へ置き換えません。
見出しのない自由記載や未対応の見出しも全文に残りますが、自動分類されないことがあります。

PCAの数値は同じ行のラベル・数字・単位が対応する場合だけ候補を作ります。
残量と積算量、持続量とボーラス量は別の項目です。別行・複数列・単位不足・
`0`と`O`の混同がある候補は、数値として確定しません。
残量から終了日時や投与量を計算せず、設定変更も行いません。

## 形式と制限

- 画像はJPEG・PNGなど、実体の形式を検査してから処理します。対応外のファイルは未対応として残します。
- PDFはテキスト層を優先し、文章のないページや画像を含むページはYomitokuで読み取ります。ページごとの処理方法を保持します。
- 1添付64MiB、30ページ、画像1ページ4,000万画素、描画合計8,000万画素、出力2MiBを上限とします。
- 初期設定では1件120秒までです。大きな資料や処理失敗は完了扱いにせず、再試行も上限を持ちます。
- 保存済みで未処理の添付も順に対象にします。削除済み・取得失敗の添付を自動で再ダウンロードする機能は追加しません。
- 訪問日の丸印やチェック欄、読みにくい手書き、機器の表示は文章だけでは正しく読めないことがあります。欄の意味や日付を推測で補いません。

Yomitokuは文書向けで、機器の液晶画面などの情景文字は得意分野とされていません。
文字起こしが保存できたことと、薬剤・病名・測定値が正しいことを区別します。
研究用の精度評価では、原画像と人による正解付けで確認してください。

## 項目設計の出典

- [厚生労働省・診療情報提供書ほかの様式](https://www.mhlw.go.jp/bunya/iryouhoken/iryouhoken15/dl/h24_02-07-30.pdf)：別紙様式11・16の項目。旧年の様式を項目設計の参考として使用。
- [日本医療情報学会・JP-CLINS診療情報提供書 v1.7.1](https://jpfhir.jp/fhir/clins/ighistory/igv1.7.1/referral-doc.html)：病名、既往・家族歴、アレルギー、身体・社会背景、処方、原資料の区別。FHIRへの適合を主張するものではありません。
- [厚生労働省・訪問看護計画書等の記載要領（2026年3月27日）](https://www.mhlw.go.jp/content/12400000/001681763.pdf)：2026年6月以降の看護報告書・記録書の項目。
- [JMS・PCA法について](https://medical.jms.cc/diagnosis/ifp/pca/04.html)：持続投与、ボーラス、ロックアウトを分ける根拠。投与量の推奨値は実装に取り込みません。
- [Yomitoku公式リポジトリ](https://github.com/kotaro-kinoshita/yomitoku)：API、CPU軽量処理、対象文書、利用条件。調査日：2026年11月5日。
