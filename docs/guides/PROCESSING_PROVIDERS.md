# 処理サービスの表示

カード見出しの日時・投稿数と同じ欄に、解析状態と処理サービスの状態を表示します。Slackではサービスの画像アイコンとローカルの💻を使い、DiscordとLINE WORKSではサービス名と状態を文字で表示します。AnthropicとOpenAIは、MCSにAPIキーを登録したサービスだけ表示します。JevとローカルLLMは常に表示します。

APIキーの登録状態は、カードを生成・更新するときに確認します。未登録・削除済みのサービスは、過去の実行記録があっても表示しません。クラウド解析を無効にしていても、キーが登録済みならサービスを表示します。登録状態はこのMacの保存形式で確認し、APIへの接続確認は行いません。

各サービスの状態は、現在の表示結果と原文に対応する実行記録から決めます。キーを登録しただけでは、処理済みにはなりません。

カード最上部は従来の固定アイコン💬を使います。投稿ごとの実行記録は詳細に残し、カード面では見出し欄だけに表示します。

## 解析状態と処理順

見出しの解析状態は表示中のページの投稿をまとめたものです。投稿ごとの要約や本文には、区間数の進捗表示を重ねません。

| 表示 | 意味 |
|---|---|
| 解析中 | 未処理の区間がある（実行待ちを含む） |
| 結果を準備中 | 区間の処理が終わり、投稿の抽出結果の確定を待っている |
| 解析完了 | 表示中の投稿の抽出処理が完了した |
| 解析未完了・要確認 | 解析を完了できず、確認が必要 |
| 状況不明 | 解析の進み具合を確認できない |

「解析完了」は抽出処理の完了を指します。本人向けの「患者の記録まとめ」では従来どおり区間数を含む処理状況を確認できます。

1投稿の採用結果に結び付く記録で順番を確認できた場合は、「採用結果の処理順: Jev → 💻」のように表示します。確認できた2サービスを先に並べ、残りのサービスは「その他（順序不明）」として分けます。

順番を確認できない場合や複数投稿をまとめて表示する場合は、「採用結果の処理順: 不明」と表示します。処理順を表示する場合も、AnthropicとOpenAIはAPIキーを登録したサービスだけを表示します。

## アイコン横の印

Slackの1投稿のカードでは次の印を使います。DiscordとLINE WORKSでは状態を文字で表示します。

| 印 | 状態 |
|---|---|
| ✓ | 現在の結果の生成・検証への関与を確認済み |
| ✓↷ | Jevで一部を実行し、残りを省略 |
| ↷ | Jevの検証を省略した記録あり |
| … | 処理待ち |
| − | 未使用 |
| ! | 失敗 |
| ? | 実行状況を確認できない |

複数投稿を表示するカードでは、表示中の投稿に実行の証拠が1件以上あれば「使用あり」、確認できなければ「不明」と表示します。「使用あり」は全投稿の処理完了を表しません。ページを切り替えると、そのページの投稿に対応する表示へ変わります。

ローカルはこのMac上のLLMを指します。記録の保存やルールによる整理の状態は、ローカルの状態判定に含みません。

実行結果が表示に採用されなかった呼出しや、過去の記録だけでは実行の有無を確認できない場合は、不明にします。クラウドへの送信後に失敗してローカル処理へ切り替わった場合も、クラウドを未使用とは断定しません。

サービスの表示は結果の生成・検証への関与を示し、Jevの検証結果の合否とは区別します。Slackではロゴの形や色を変えず、別の印で状態を示します。代替テキストにはサービス名と状態を含めます。

SlackではAnthropic・OpenAI・Jevの画像とローカルの💻を使います。画像を並べられない通知先では、サービス名と状態を文字で表示します。

素材の出典とライセンスは [アイコンの説明](../../resources/provider-icons/README.md)を参照してください。同梱素材は説明図にも使い、Slackでは固定の公開URLから画像を表示します。URLに投稿内容や患者情報を付加しません。
