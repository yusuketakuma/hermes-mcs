# 処理サービスの表示

カード見出しの日時・投稿数と同じ欄に、解析状態と処理サービスの状態を表示します。Slackではサービスの画像アイコンとローカルの💻を使い、DiscordとLINE WORKSではサービス名と状態を文字で表示します。新形式では、現在の結果への関与・一部実行・処理待ち・失敗を確認できるサービスだけ表示します。未使用・省略のみ・状況不明のサービスは見出しから省きます。AnthropicとOpenAIは、APIキーを登録したサービスが表示対象です。

APIキーの登録状態は、カードを生成・更新するときに確認します。未登録・削除済みのサービスは、過去の実行記録があっても表示しません。クラウド解析を無効にしていても、キーが登録済みなら表示対象に含まれますが、見出しへの表示は実行記録の状態によります。登録状態はこのMacの保存形式で確認し、APIへの接続確認は行いません。

各サービスの状態は、現在の表示結果と原文に対応する実行記録から決めます。キーを登録しただけでは、処理済みにはなりません。

カード最上部は従来の固定アイコン💬を使います。投稿ごとの実行記録は詳細に残し、カード面では見出し欄だけに表示します。

## 解析状態と処理順

見出しの解析状態は表示中のページの投稿をまとめたものです。新形式では、投稿ごとの要約や本文に区間数の進捗表示を重ねません。

| 表示 | 意味 |
|---|---|
| ◐ 未完了 | 未処理の区間がある、または抽出結果の確定待ち（実行待ちを含む） |
| ✓ 完了 | 表示中の投稿の抽出処理が完了した |
| ! 要確認 | 解析を完了できず、確認が必要 |
| ? 状況未取得 | 解析の進み具合を確認できない |

「✓ 完了」は抽出処理の完了を指します。本人向けの「患者の記録まとめ」では従来どおり区間数を含む処理状況を確認できます。

1投稿の採用結果に結び付く記録で順番を確認できた場合は、その順でサービスを並べます。見出しには「採用結果の処理順」や「その他（順序不明）」の説明文を重ねません。順番を確認できないサービスの並びは、実行順を表しません。

新形式への更新前のカードでは、従来の解析状態・処理順の説明・サービスの状態を表示する場合があります。旧表示ではJevとローカルを常に表示し、未使用・省略・不明も区別します。

## アイコン横の印

新形式では次の印を使います。Slackでは画像アイコンや💻に添え、DiscordとLINE WORKSではサービス名に添えます。

| 印 | 状態 |
|---|---|
| ✓ | 現在の結果の生成・検証への関与を確認済み |
| ◐ | Jevで一部を実行し、残りを省略 |
| ● | 複数投稿のうち、実行の証拠がある投稿を含む |
| … | 処理待ち |
| ! | 失敗 |

複数投稿を表示するカードでは、表示中の投稿に実行の証拠が1件以上あれば「●」で使用ありを示し、確認できないサービスは新形式の見出しでは省きます。使用ありは全投稿の処理完了を表しません。ページを切り替えると、そのページの投稿に対応する表示へ変わります。

ローカルはこのMac上のLLMを指します。記録の保存やルールによる整理の状態は、ローカルの状態判定に含みません。

実行結果が表示に採用されなかった呼出しや、過去の記録だけでは実行の有無を確認できない場合は、不明にします。クラウドへの送信後に失敗してローカル処理へ切り替わった場合も、クラウドを未使用とは断定しません。

サービスの表示は結果の生成・検証への関与を示し、Jevの検証結果の合否とは区別します。Slackではロゴの形や色を変えず、別の印で状態を示します。代替テキストにはサービス名と状態を含めます。

SlackではAnthropic・OpenAI・Jevの画像とローカルの💻を使います。画像を並べられない通知先では、サービス名と状態を文字で表示します。

素材の出典とライセンスは [アイコンの説明](../../resources/provider-icons/README.md)を参照してください。同梱素材は説明図にも使い、Slackでは固定の公開URLから画像を表示します。URLに投稿内容や患者情報を付加しません。
