# ローカル患者タイムライン

患者をチャンネルとして選び、保存済みの投稿を古い順に閲覧するSlack風の画面です。
外部チャットのアカウント・SDK・CDN・クラウド推論は不要です。macOSのローカル操作者が明示的に起動する閲覧専用機能（薬局の患者台帳を指定したときだけ台帳を編集できます）で、既存のSlack・Discord・LINE WORKS連携は残します。

## 起動

導入先のPython環境で、公開済みスナップショットと閲覧を許可する患者IDを指定します。
原本の `ledger.db` は指定できません。スナップショットを外部へコピーしないでください。

```sh
python3 mcs/ops/mcs_local_chat.py \
  --snapshot /path/to/mcs/data/snapshots/ledger-snapshot.db \
  --project 101 --project 102
```

表示された秘密URLを**同じMacのブラウザ**で開きます。URLを共有・外部チャットへ投稿しないでください。
ポートは空き番号を自動選択します。固定する場合は `--port 8765`。終了は `Ctrl+C` です。
全患者を表示する権限を持つローカル操作者だけが `--project` の代わりに `--all-patients` を指定できます。
患者範囲の指定なしでは起動しません。この指定は既存の外部チャット利用者の権限を継承・拡張するものではありません。

通常の起動は、OSアカウントへのアクセス権を持つローカル操作者向けです。自動起動・インストール・LANアクセスは追加しません。
事業所のスマホから使うときは、下の「スマホから使う（常駐モード）」で Tailscale の tailnet の中だけに公開します。

## 使い方

- 左の患者一覧を選択。患者名・IDで絞り込めます。
- 患者名の右に、その患者の保存済みコンテキストを表示します。「背景・根拠をすべて表示」で分類別の記録・対象者・日付・根拠を確認できます。狭い画面では患者名の下に表示します。
- 本文・投稿者の検索は選択中の患者だけを対象にし、返信も検索します。
- 通常は直近50件の親投稿を古い順で表示。「以前の投稿」で過去へ進みます。
- 「詳細・返信」で元投稿・返信・メンション等の状態・構造化記録・添付を表示します。
- 「記録の要約」は既存通知と同じ `structured_view.structured_lines` の有効な投影です。
- 添付は取得状態と保存済みのOCR文字記録のみ。PDFや画像の原本は配信しません。
- 検索欄の左の「表示する内容」で、タイムラインのほかに患者別の画面を選べます。記録のまとめ（未完了タスク・抽出の処理状況を含む）、患者さんの全体像、前回から変わったこと、連絡・返答の確認、訪問前の確認ノート、経過タイムライン、出来事・検査・観測の記録、記録の食い違い、引継ぎ用の記録、退院・移行時の経過、未解消のシグナルです。中身は通知カードの同名の画面と同じ `notify_views` の投影です。
- 「前回から変わったこと」は閲覧の記録を残さないため、毎回直近7日を基準に表示します。「直近」「今後」などの期間は、閲覧した時刻ではなくスナップショットを作った時刻を基準にします。
- 未解消のシグナルは、すべての種類の判定が終わったことを確認できないときはその旨を表示し、該当がなくても「ありません」とは断定しません。
- 投稿の詳細の「この投稿の薬剤を表示」で、通知カードの💊と同じ薬剤の一覧を表示します。返信の薬剤は、返信の「添付・記録の状態」から開く「この返信の薬剤を表示」で確認します。一覧に出る「誤りを報告」の案内は通知カードの操作で、この画面からは報告できません。
- 「更新」は公開スナップショットを読み直します。自動取得・新しい解析は行いません。

時刻はJSTの投稿時刻です。本文に書かれた出来事の日付を並び順へ読み替えません。
複数行のコンテキストは、後続の本文がすべて同じ分類とは限りません。明示的な見出し行と、分類範囲を確認できない原文全体を分けて表示します。続きや但し書きは削除せず、原文全体から確認できます。対象者や現在の状態は推測しません。
本文や返信の未取得・履歴全体の取得未確認を明示します。検索結果なしは対応なしを意味しません。
公開スナップショットが置換された場合、古いページ送りは拒否されます。「更新」で読み直してください。

## 在宅ケアの患者台帳（任意）

`--homecare-db` を付けて起動すると、MCS とは別に事業所の患者台帳と職員の名簿を同じ画面で扱えます。
在宅業務の記録（旧 zaitaku-calender の機能）をこのMacへ移すための土台で、職種に共通の機能（コア）の上に職種別のモジュールを載せる作りです。今は薬局モジュールだけがあり、`--homecare-module pharmacy`（既定）で有効になります。`--homecare-db` を付けなければ、これまでどおり閲覧専用です。

```sh
python3 mcs/ops/mcs_local_chat.py \
  --snapshot /path/to/mcs/data/snapshots/ledger-snapshot.db --all-patients \
  --homecare-db /path/to/mcs/data/homecare.db
```

- 台帳のファイルは初回に作られます（ファイル 0600・フォルダ 0700）。原本の `ledger.db` とスナップショットには書き込みません。
- 置き場所は `MCS_ROOT` の `data/homecare.db` を使ってください。今の版の定期バックアップと暗号化バックアップは、この台帳をまだ含みません（対応は別に進めています）。それまでは、サーバーを止めてから台帳のファイルを自分で複製して保管してください。
- 左上の切替で「MCS」「薬局の患者」「職員」を選びます。初回は職員の画面が開くので、まず自分を登録します。最初の1人だけは操作者なしで登録でき、その人がそのまま操作者と管理者になります。
- 職員には資格（事務・その他と、有効なモジュールの資格。薬局なら薬剤師）を1つ以上付けます。職員の登録と変更は管理者だけができ、自分自身を退職や管理者以外に変えることはできません。
- 患者ごとの「ケアチーム」で、この事業所の担当者を役割ごとに決めます。薬局モジュールの役割は「担当薬剤師」で、薬剤師の資格を持つ在籍中の職員だけを選べます。別の人を担当にすると前の担当は外れ、交代の履歴が残ります。
- 2件目以降の登録・変更は、左の「操作者」で選んだ在籍中の職員の名前で記録します。誰がいつ何をどう変えたかを、変更前と変更後の両方で残します。
- 通常の起動では「操作者」は本人確認ではなく、起動したURLを開ける人なら誰でも選べます。URL を渡す相手を管理者と同じ扱いにしてください。常駐モードでは、操作者は Tailscale のログインで決まり、画面からは選べません。
- 事務員（資格「事務」）も、患者台帳・訪問予定・処方の入力・訪問ルートを使えます。訪問薬剤管理を「実施」にできるのは、薬剤師の資格を持つ職員が記録し、訪問した職員も薬剤師の場合だけです。実施済みの訪問薬剤管理の訂正も同じです。配薬のみの訪問は事務員も実施にできます。
- 担当を持っている職員は、退職扱いにしたり担当に必要な資格を外したりする前に、担当を交代するか外してください。そのままでは保存しません。
- 優先連絡先には電話番号が必要です（本人なら本人電話、キーパーソンなら氏名・続柄・電話、施設・その他なら優先連絡先の電話）。
- 保存は読み込んだ版に対してだけ行います。ほかの人が先に更新していたら保存せず、入力を残したまま知らせます。
- 薬局の患者と MCS の患者は、人が選んだときだけ1対1で対応付けます。氏名が完全に一致する MCS の患者は候補として出しますが、自動では対応付けません。対応付けと解除の履歴は消えません。
- 対応付けた患者は、MCS の画面の患者名の下に台帳の氏名を表示し、台帳の画面から MCS のタイムラインを開けます。対応付けられるのは起動時に許可した患者範囲の中だけです。

### 訪問と処方

- 患者の画面の「訪問」で、訪問を予定し、実施・中止を記録します。種類はモジュールが決めます（薬局なら「訪問薬剤管理」「配薬のみ」）。実施にするときは訪問した職員が必要です。訪問を別の患者へ付け替えることはできません。
- 薬局モジュールの「処方」で、処方日・医療機関・処方医と薬剤（名前・用量・用法・日数）を記録します。薬剤は入力した名前をそのまま残すので、薬剤マスターが更新されても過去の処方の表示は変わりません。薬剤名の一部を入れて「マスターから選ぶ」を押すと、承認済みの薬剤マスター（`drug_map`）から候補を選べ、その公式コードも一緒に保存します。薬剤マスターが未設定・未承認のときは候補が出ないので、薬剤名だけで登録します。選んだ後に薬剤名を書き換えると、コードは保存されません。
- 「訪問時の情報を開く」で、住所・優先連絡先・アクセス・注意事項、ケアチーム、次の予定と最近の実施、最近の処方、MCS のタイムラインへの入口を1画面にまとめて見られます。MCS の患者と対応付けてあれば、公開スナップショットから「訪問前の確認」「前回から変わったこと」「患者背景」「返信待ち」と未解消のシグナルも同じ画面に出します。「前回から変わったこと」は最後に実施した訪問（開始時刻がなければその日の0時）からの変化で、実施済みの訪問がなければ直近7日の変化です。「訪問前の確認」などの記録の節に8件を超える記録があるときは、節ごとの「次のページ」で同じスナップショット・同じ基準のまま続きを開けます（スナップショットが更新されていれば読み直しを求めます）。未解消のシグナルは新しい順に50件までをまとめて表示し、続きはタイムラインの画面で確認します。
- 左上の「訪問予定」で、日付ごとの訪問の一覧を見られます。

### 訪問ルート（任意・外部送信あり）

`--route-settings` に設定ファイルを指定すると、「訪問予定」の画面で、その日の予定の訪問を回る順番と到着の目安を作れます。
**この機能は患者の住所を外部のサービスへ送ります。** 送るのは「ルートを作る」を押したときだけで、送る内容は次の2つです。

- 住所の文字列を国土地理院の住所検索（`msearch.gsi.go.jp`）へ送り、緯度・経度に変えます。変換した位置は台帳に保存し、住所が変わるまで同じ住所は送りません。
- 出発地と訪問先の緯度・経度、時刻を決めた訪問の時刻の幅を openrouteservice（`api.openrouteservice.org`）へ送り、道路に沿って回る順番を受け取ります。訪問は送るたびに振る通し番号で区別し、台帳の ID は送りません。

氏名・ID・電話番号・注意事項・メモは送りません。時刻を決めた訪問には、その前後15分に着く順番だけを作ります。間に合わない訪問は順番に入れず、件数を別に表示します。
住所から場所が分からなかった訪問と、検索結果が離れた複数の場所にまたがる住所（番地のない「中央区」など）は、推測で順番に入れず、件数を別に表示します。
設定ファイルの `depart_time`（`HH:MM`、省略時は `09:00`）を出発時刻として、訪問を始められる見込みの時刻を表示します。予定の時刻より早く着く場合は、その時間枠が始まる時刻を出します。
設定ファイルは所有者だけが読める JSON（`chmod 600`）で、openrouteservice の無料キーと出発地（事業所）の住所を書きます。

```json
{"openrouteservice_key": "（取得したキー）", "origin_address": "（事業所の住所）", "depart_time": "09:00"}
```

キーは openrouteservice のサイトで無料のアカウントを作って発行します。無料枠には1日あたりの回数の上限があります。

## スマホから使う（常駐モード）

1台の Mac で1つの事業所を扱います。Mac mini 以外の端末（スマホなど）から使う場合だけ、Mac と職員のスマホを同じ Tailscale の tailnet に入れます。

### インストーラーで設定する（推奨）

1. 導入時に `install.sh --with-tailscale`（または `mcs install --with-tailscale`）を実行します。段階1で Tailscale アプリ（Homebrew の `tailscale-app`）を入れます。この選択は保存され、後の更新・再導入でも引き継ぎます。`--with-tailscale` を付けない Mac には入れません。
2. Tailscale アプリを開き、事業所の Tailscale アカウントでサインインします。管理画面で MagicDNS と HTTPS 証明書を有効にします。
3. `mcs setup remote` を実行します。この Mac の Tailscale の名前を確かめて設定に保存し、`tailscale serve --bg http://127.0.0.1:8770` で tailnet に公開し、患者画面を常駐サービス（`ai.mcs.local-chat`）として登録します。患者は公開スナップショットの全員、台帳は `data/homecare.db` です。待ち受けの番号は `--port`、訪問ルートの設定ファイルは `--route-settings` で指定できます。公開スナップショットがまだ作られていない間は常駐サービスが起動に失敗し、30秒ごとに起動し直します。最初の収集が終わると開けるようになります。
4. スマホにも Tailscale を入れて同じアカウントでサインインし、表示された `https://<名前>.<tailnet>.ts.net/` を開きます。

やめるときは `mcs setup remote --off` で常駐サービスを止め、`tailscale serve status` を確かめてから `tailscale serve reset` で公開を止めます。

### 手で起動する

Mac の名前（`<名前>.<tailnet>.ts.net`）を確かめてから、固定のポートで起動します。例の `example-mac.example-tailnet.ts.net` は、この Mac の Tailscale の名前に置き換えてください。

```sh
python3 mcs/ops/mcs_local_chat.py \
  --snapshot /path/to/mcs/data/snapshots/ledger-snapshot.db --all-patients \
  --homecare-db /path/to/mcs/data/homecare.db \
  --port 8770 --tailnet-host example-mac.example-tailnet.ts.net
```

サーバーは起動した端末で動き続けます。別の端末で次を一度だけ実行し、tailnet へ公開します（`--bg` の設定は Mac を再起動しても残ります）。

```sh
tailscale serve --bg http://127.0.0.1:8770
```

- `tailscale serve` は tailnet の中だけに HTTPS で公開します。`tailscale funnel` は一般のインターネットに公開するので使いません。
- 職員はスマホのブラウザで `https://<名前>.<tailnet>.ts.net/` を開きます。秘密の URL はなく、Tailscale のログインで誰かを見分けます。
- 職員として登録した Tailscale のログイン名（職員の画面の「Tailscale のログイン名」）と一致し、在籍中の職員だけが使えます。登録のないログインには、MCS の記録も台帳も表示しません。
- 職員がまだ1人もいないときだけ、最初に開いた人が自分を登録できます。その人の Tailscale のログインが結び付き、管理者になります。続く職員は管理者が登録し、各自のログイン名を入れます。
- 管理者は、まだ登録していない自分のログイン名を登録できます。登録済みのログイン名を自分で変えたり消したりはできません（次から自分で開けなくなるため）。変えるときは、別の管理者に頼んでください。
- すでに職員を登録した台帳を常駐モードで開くときは、先に通常の起動で、在籍中の管理者に Tailscale のログイン名を登録しておきます。登録しないまま常駐モードにすると誰も使えないので、通常の起動に戻ってログイン名を登録してから、もう一度常駐モードにします。
- tag を付けた端末からのアクセスには Tailscale がログインを付けないため、使えません。
- 同じ Mac の別のプロセスはログインを偽れるので、Mac は単一ユーザーで運用してください。

## 完全合成デモ

実患者・匿名化した実投稿は使いません。次のコマンドは新規ディレクトリだけに完全合成データを作ります。

```sh
python3 scripts/development/local_chat_demo.py --output /path/to/new-synthetic-demo
python3 mcs/ops/mcs_local_chat.py \
  --snapshot /path/to/new-synthetic-demo/snapshots/ledger-snapshot.db \
  --all-patients
```

## 外部チャット表示との対応範囲

比較対象は `adapters/{slack,discord,lineworks}/cards.py` と、共通の `notify_render`・`structured_view`・`adapters/common/context_view.py`・`summary.py` です。
本機能は閲覧の入口をローカルへ追加するもので、外部チャットの全表示を完全に置換するリリースではありません。

| 既存画面に表示される内容 | ローカル画面 |
| --- | --- |
| 患者名・投稿者・職種・所属・投稿日時・原文・返信 | 対応。患者範囲をサーバー側で毎回検証 |
| 投稿ごとの要約、薬剤・バイタル・依頼など | 対応。通知と同じ有効性・削除・患者スコープ判定の `structured_lines` を再利用 |
| 投稿のスタンプ件数・取得状態・押した人 | 既存evidence投影と共通フォーマッターで表示。投影が許す範囲の氏名のみ |
| メンション・しおり・ピン留め | 詳細で取得状態を表示。変更不可 |
| 投稿に紐づく構造化背景情報 | 詳細で原文に結び付いた有効な項目・属性を表示 |
| 添付の名前・取得状態・OCR文字記録 | 対応。署名URL・ローカルパス・ファイル配信なし |
| 添付PDF・画像の閲覧／ダウンロード | **未対応**。本機能から原本を開かない |
| 患者全体の26分類の背景情報 | 患者名の右で既存background投影を表示。全分類の記録と根拠を展開可能。未取得は空欄として明示 |
| 患者全体の経過／訪問前確認・変化・食い違い・引継ぎなどの画面 | 対応。「表示する内容」から通知カードと同じ投影を表示。測定値の原文記録（Slackのみ）は未対応 |
| 投稿ごとの薬剤（💊） | 対応。投稿の詳細から表示 |
| 未解消のシグナル | 対応。種別・内容・検出時刻と根拠の投稿 |
| 未完了タスク・患者単位の抽出の処理状況 | 対応。「記録のまとめ」に表示 |
| 横断サマリー・薬剤辞書の検索・処理プロバイダー進捗 | **未対応**。既存ローカルCLI／外部チャット表示を継続 |
| 確認者・担当者・誤り報告・配送／取り下げ状況 | **未対応**。通知カード固有の状態はこの画面では表示しない |
| 送信・既読化・スタンプ・承認操作・予定配信 | 対象外。書込み経路や定期処理を追加しない |

## データ境界

既存の `View` / `LedgerReader(mode=ro)` が検証した公開スナップショットだけを読みます。
患者データはHTMLへ埋め込まず、同一オリジンの秘密URL以下から読み込み、DOMの `textContent` で表示します。
ブラウザへの応答は `no-store`、外部リソース・フレーム・フォーム送信はCSPで遮断し、アクセスログへURLや検索語を出力しません。
起動ごとの秘密URLと厳密なHost・Origin・Fetch Metadata検証で、別サイトからの読取りやDNS rebindingを拒否します。
ブラウザ履歴や画面には患者情報が残り得ます。共有ブラウザを使わず、閲覧後はタブとサーバーを閉じてください。
薬局の患者台帳への書込みは、同一オリジンからの `fetch` だけを受け付けます。Origin ヘッダー（`Sec-Fetch-Site` を送るブラウザでは、その値が `same-origin` であること）、起動ごとに変わる書込み用の値（`X-MCS-CSRF`）、`application/json`、64KiB 以下の本文がそろわない要求は保存しません。
エラーは固定の符号だけを返し、入力値や患者情報を含めません。
訪問ルートを設定した場合だけ、上の「訪問ルート」に書いた住所と位置を、固定の2つの宛先へ HTTPS で送ります（proxy 無効・redirect 拒否）。
