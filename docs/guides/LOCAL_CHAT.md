# ローカル患者ワークスペース

患者を選び、保存済みの投稿を古い順に閲覧しながら、MCS から取得した情報（投稿・添付・スタンプ・連携サマリー・MCS の登録データなど）を患者ごとに確認する「患者ワークスペース」の画面です。
外部チャットのアカウント・SDK・CDN・クラウド推論は不要です。macOSのローカル操作者が明示的に起動する閲覧専用機能（薬局の患者台帳を指定したときだけ台帳を編集できます）で、既存のSlack・Discord・LINE WORKS連携は残します。

## 起動

導入先のPython環境で、公開済みスナップショットと閲覧を許可する患者IDを指定します。
原本の `ledger.db` は指定できません。スナップショットを外部へコピーしないでください。

```sh
python3 mcs/ops/mcs_local_chat.py \
  --snapshot /path/to/mcs/data/snapshots/ledger-snapshot.db \
  --project 101 --project 102
```

表示された秘密URLを**同じMacのブラウザ**で開きます。URLを共有・外部チャットへ投稿しないでください。
ポートは空き番号を自動選択します。固定する場合は `--port 8765`。終了は `Ctrl+C` です。
全患者を表示する権限を持つローカル操作者だけが `--project` の代わりに `--all-patients` を指定できます。
患者範囲の指定なしでは起動しません。この指定は既存の外部チャット利用者の権限を継承・拡張するものではありません。

通常の起動は、OSアカウントへのアクセス権を持つローカル操作者向けです。自動起動・インストール・LANアクセスは追加しません。
事業所のスマホから使うときは、下の「スマホから使う（常駐モード）」で Tailscale の tailnet の中だけに公開します。

## 使い方

- 画面の上は見出しです。MCS の画面では、患者名（同じ名前の患者がいるときは「名（施設） #末尾4桁」、グループのルームは「グループ名 #ID」）の下の行に、ID・施設名・グループ名・病名・保存件数・最終投稿日・最終取得（完了した取得の日時）を表示します。その行の右に札を並べます。アーカイブ、取得状態、「履歴全体の取得は未確認」、初回取込の状態、「未解消シグナル」「返答確認」、「MCSで開く ↗」（MCS のその患者のルームを別タブで開く外部リンク。グループのルームには出ません）です。右端にスナップショットの時刻と経過時間（「N分前」「N時間前」）と「更新」を表示します。スマホの MCS の画面では、見出しの行は「患者」ボタン（患者一覧を開く）、患者名、「更新」だけになり、ID などの行・札・スナップショットの時刻をその下の行に表示します（データの新しさを確かめられるように残しています）。患者台帳・訪問予定・職員の画面では、スナップショットの時刻は表示しません。
- 左の患者一覧から患者を選びます。患者名・IDで絞り込めます。一覧は最近の投稿があった順（投稿日時が分からない患者は最後）に並びます。各行には、ID・施設名やグループ名・最終投稿日、病名、保存件数、未解消のシグナルの札（「シグナル N」。判定が終わっていないときは「シグナル N+」「シグナル 判定中」、取得できないときは「シグナル 不明」）が出ます。返答確認の件数は一覧には出ません。スマホでは一覧が出ておらず、上の「患者」ボタンで全画面の一覧を開きます（「スマホから使う」を参照）。
- 見出しの下に、その患者の保存済みコンテキストを要点として横に並べて表示します（アレルギーの記録を先頭に置き、スマホでは先頭の2分類）。「背景・根拠をすべて表示」で、MCS の「連携サマリー」のカード、コンテキストのまとめ、分類別の記録・対象者・日付・根拠を確認できます。連携サマリーのカードは、全文・MCS 上の更新日時・更新した職種を表示します。取得していないときは「未取得」、取得に失敗したときは「取得失敗」、MCS の記載が空のときは「空（MCS に記載がありません）」と、それぞれ区別して表示します。最新の取得に失敗したが以前の内容があるときは、以前の内容に「前回取得した内容を表示しています」と添えます。要点の下の1行は、連携サマリーの要旨・反映時点・取得と解析の状況（完了していない範囲）をまとめた完全性の行で、押すと上の展開部分が開きます。分類別の記録がなくても、この行と展開部分で連携サマリーと取得状況を確認できます。
- 検索欄は選択中の患者だけを対象に、投稿の本文と添付のOCR文字記録（保存済みのもの）を検索します（返信の本文も含みます）。投稿者の名前では検索しません。空白で区切った語は、すべてを含むものだけが一致します。結果には「本文」「添付OCR Nページ」の別が付き、「投稿を開く」で該当の投稿の詳細へ移ります。検索しなかった範囲は結果の下に書きます（まだ調べていない範囲があるとき・OCR が未完了のとき・本文を取得できていないとき・OCR が設定で無効なときなど）。「続きを検索」で次の範囲へ進みます。アーカイブ済み・閲覧権限のない患者では検索せず、その旨を表示します。検索結果なしは、検索した範囲に該当がなかったことを示すだけで、記録がないことを意味しません。
- 通常は直近50件の親投稿を古い順で表示。「以前の投稿」で過去へ進みます。
- 各投稿は、投稿者（自分の投稿は「（自分）」、自分の事業所の投稿は「自事業所」）・職種・所属・時刻の行と本文で表示します。同じ行に、緊急度の札（「🚨 緊急度高」「🚨」。監査で通常判定・判断保留になった投稿はその旨を併記し、札に触れると根拠の引用が出ます）と、確認が必要な投稿の札（「急ぎの確認依頼（本人の緊急状態とは別）」「緊急度: 要確認（対象人物・時点の根拠を確認）」）が付きます。本文が空で全文を取得済みの投稿（ファイルだけの投稿など）は「本文なし」、本文を取得できていない投稿は「本文未取得」、削除を観測した投稿は「削除された投稿」と表示します。
- 本文の下の行に「詳細・返信」「添付 N件」（取得失敗・未取得があるときは件数を添えて強調）と、記録の状態を示す札を並べます。札は、最新の返信（「最新返信 時刻 投稿者・職種」。未取得の返信があるときはその旨）、「要約 処理待ち」「要約 作成失敗」（記録の要約が作られていない投稿。作成済みなら出ません）、「@自分宛て」「ピン留め」「ブックマーク」（観測できたものだけ。取得していない状態は詳細の「記録の状態」に出ます）、「変更を検知」「削除を観測」、スタンプ（取得状態、押した人の名前、「自分のスタンプ」）、「本文は一部未取得です」、「未取得の返信があります」、医師の「見ました」の観測状況です。
- 「変更を検知」「削除を観測」の時刻は、このシステムが収集時に変化を見つけた時刻です。MCS の投稿者が編集・削除した時刻ではなく、変更前の本文は保存していません。表示がないことは、編集されていないことを意味しません。
- 「詳細・返信」で元投稿・返信・メンション等の状態・構造化記録・添付を表示します。スタンプは、詳細で「押した人」を絵文字・名前・職種で表示します（押した人の一覧が古いときは「古い情報」、取得に失敗したとき・未取得のときはその旨）。自分の投稿には、自分以外が押したスタンプを表示します。自分が押したスタンプは「自分のスタンプ」の札で示します。
- 「記録の要約」は既存通知と同じ `structured_view.structured_lines` の有効な投影です。
- 添付は、ファイルの状態（取得済み・未取得・取得失敗・原本保持期間終了）と取得失敗の理由、大きさ、OCR文字記録の状態（作成済み・文字なし・未作成・作成に失敗・対応していない形式・原本がないため作成できない・表の読み取りが不確かなため除外）、保存済みのOCR文字記録をページごとに表示します。文書の見出しなど、OCR から見つかった項目があれば併せて表示します。OCR の表の読み取りが不確かで除外した添付には、MCS で原本を確認するリンク（MCS のページを別タブで開く外部リンク）を表示します。PDFや画像の原本はこの画面からは開けません。
- 検索欄の左に並ぶタブで、タイムラインのほかに患者別の画面を選べます（幅が足りないときはタブを横にスクロールします）。記録のまとめ（未完了タスク・抽出の処理状況を含む）、患者さんの全体像、前回から変わったこと、連絡・返答の確認、訪問前の確認ノート、経過タイムライン、出来事・検査・観測の記録、記録の食い違い、引継ぎ用の記録、退院・移行時の経過、未解消のシグナルです。これらの中身は通知カードの同名の画面と同じ `notify_views` の投影で、一覧を表示しきれないときは「他N件」と残りの件数を示します。最後のタブ「MCS登録データ」は別の記録で、下の「MCS登録データ」に書きます。
- 「前回から変わったこと」は閲覧の記録を残さないため、毎回直近7日を基準に表示します。「直近」「今後」などの期間は、閲覧した時刻ではなくスナップショットを作った時刻を基準にします。
- 未解消のシグナルは、すべての種類の判定が終わったことを確認できないときはその旨を表示し、該当がなくても「ありません」とは断定しません。
- 投稿の詳細の「この投稿の薬剤を表示」で、通知カードの💊と同じ薬剤の一覧を表示します。返信の薬剤は、返信の「添付・記録の状態」から開く「この返信の薬剤を表示」で確認します。一覧に出る「誤りを報告」の案内は通知カードの操作で、この画面からは報告できません。
- 「更新」は公開スナップショットを読み直します。自動取得・新しい解析は行いません。
- 取得の状態は見出しの札で示します。取得が完了していないとき（未取得・一部未取得・一部取得・取得失敗・閲覧権限なし）と、履歴全体の取得が未確認のときだけ、「履歴全体の取得は未確認」などの札が出ます。理由が分かるときは「取得失敗（時間切れ）」のように併記します。札に触れると取得状態の文言と最終取得の日時（完了した取得がなければその旨）が出ます。初回取込中の患者には「初回取込中」（保留のときは「初回取込 保留」、状態を確認できないときは「初回取込 状態不明」）の札が付きます。
- 見出しの「未解消シグナル」「返答確認」の札は、押すと同名のタブが開きます。「未解消シグナル N」は件数、「未解消シグナル N以上（判定中）」は判定がまだ終わっていない投稿があり、判定済みの範囲では N 件という意味です（0件とは言えません）。「判定中」は、判定が終わった範囲に該当がまだ見つかっていない状態です。「取得できません」は件数を読み取れなかったという意味で、0件ではありません。「返答確認 依頼 N（返答が見つからない M・確認できない K）」は、保存済みの記録に返答が見つからない、または返答の有無を確認できない依頼の件数です。対応がなかったという意味ではありません。
- 投稿を開いていない間、幅1200px以上の画面では右の欄に「いまの状況」を表示します。未解消のシグナルと「連絡・返答の確認」を各5件まで並べ、続きは各カードの「すべて見る」で対応するタブに開きます。投稿の「詳細・返信」を開くと、この欄が投稿の詳細に替わります。1200px未満では「いまの状況」の欄は出さず、投稿の詳細は画面に重ねて開きます。そのため1200px未満（スマホを含む）では、未解消のシグナルと返答確認は見出しの札から確認します。

時刻はJSTの投稿時刻です。本文に書かれた出来事の日付を並び順へ読み替えません。
複数行のコンテキストは、後続の本文がすべて同じ分類とは限りません。明示的な見出し行と、分類範囲を確認できない原文全体を分けて表示します。続きや但し書きは削除せず、原文全体から確認できます。対象者や現在の状態は推測しません。
本文や返信の未取得・履歴全体の取得未確認を明示します。検索結果なしは対応なしを意味しません。
公開スナップショットが置換された場合、古いページ送りは拒否されます。「更新」で読み直してください。
見出しのスナップショットの時刻の横に経過時間を表示し（1分ごとに更新）、投稿の下にも「表示は ○○ JST（N分前）時点のスナップショットです。」と書きます。スナップショットに注意事項があるときは、同じ行に追記します（履歴をすべて取得できたかは確認できていない、MCS の現在の状態より遅れている場合がある、など）。ローカルのサーバーに接続できないとき・応答を読み取れないときも、その旨を表示します。

## MCS登録データ

タブ「MCS登録データ」は、MCS の患者情報に登録されたデータを表示します。チャットの投稿とは別の記録です。
「薬剤登録」「観測項目」「観測値」のカードに分かれ、カードごとに取得の状態を札で示します。「取得済み」「登録行なし」「未取得・未確認」「取得失敗」「古い・定義変更あり」のいずれかで、最終取得・最終試行の日時と理由コードが分かるときは併記し、以前の記録だけのときは「過去の記録」の札が付きます。取得していない・失敗・古いカードは、行が表示できないことを明記します。
薬剤登録は開始・終了・薬剤名、観測項目は項目・単位・基準、観測値は日時と値（最高・最低・左・右がある項目はその値）を表にします。行は先頭の200件までで、それを超える分は「他N件」と件数だけを示します。
ケアチームの氏名は表示しません。収集設定で登録データの収集が無効のときは、その旨と「表示は以前に取得した記録だけ」であることを表示します。次の場合は表を出さず理由を書きます。

- スナップショットが古い形式のとき: 登録データを読み取れない旨を表示します。
- MCS の医療記録との対応付けを確認できない患者とグループのルーム: 登録データは取得していない旨を表示します。

## 在宅ケアの患者台帳（任意）

`--homecare-db` を付けて起動すると、MCS とは別に事業所の患者台帳と職員の名簿を同じ画面で扱えます。
在宅業務の記録（旧 zaitaku-calender の機能）をこのMacへ移すための土台で、職種に共通の機能（コア）の上に職種別のモジュールを載せる作りです。今は薬局モジュールだけがあり、`--homecare-module pharmacy`（既定）で有効になります。`--homecare-db` を付けなければ、これまでどおり閲覧専用です。

```sh
python3 mcs/ops/mcs_local_chat.py \
  --snapshot /path/to/mcs/data/snapshots/ledger-snapshot.db --all-patients \
  --homecare-db /path/to/mcs/data/homecare.db
```

- 台帳のファイルは初回に作られます（ファイル 0600・フォルダ 0700）。原本の `ledger.db` とスナップショットには書き込みません。
- 置き場所は `MCS_ROOT` の `data/homecare.db` を使ってください。この場所にある台帳は、日次のローカルバックアップと更新前のコピーの対象です（[バックアップ](BACKUP.md)の「ローカル日次 backup の確認と復元」）。暗号化した外部バックアップは、この台帳をまだ含みません。外部にも残したいときや、台帳をほかの場所に置いたときは、サーバーを止めてから台帳のファイルを自分で複製して保管してください。
- 左上の切替で「MCS」「患者台帳」「訪問予定」「職員」を選びます（スマホでは画面の下のタブバー）。初回は職員の画面が開くので、まず自分を登録します。最初の1人だけは操作者なしで登録でき、その人がそのまま操作者と管理者になります。
- 職員には資格（事務・その他と、有効なモジュールの資格。薬局なら薬剤師）を1つ以上付けます。職員の登録と変更は管理者だけができ、自分自身を退職や管理者以外に変えることはできません。
- 「患者台帳」の「台帳を編集」にある患者ごとの「ケアチーム」で、この事業所の担当者を役割ごとに決めます。薬局モジュールの役割は「担当薬剤師」で、薬剤師の資格を持つ在籍中の職員だけを選べます。別の人を担当にすると前の担当は外れ、交代の履歴が残ります。
- 2件目以降の登録・変更は、左の「操作者」で選んだ在籍中の職員の名前で記録します。誰がいつ何をどう変えたかを、変更前と変更後の両方で残します。
- 通常の起動では「操作者」は本人確認ではなく、起動したURLを開ける人なら誰でも選べます。URL を渡す相手を管理者と同じ扱いにしてください。常駐モードでは、操作者は Tailscale のログインで決まり、画面からは選べません。
- 事務員（資格「事務」）も、患者台帳・訪問予定・処方の入力・訪問ルートを使えます。訪問薬剤管理を「実施」にできるのは、薬剤師の資格を持つ職員が記録し、訪問した職員も薬剤師の場合だけです。実施済みの訪問薬剤管理の訂正も同じです。配薬のみの訪問は事務員も実施にできます。
- 担当を持っている職員は、退職扱いにしたり担当に必要な資格を外したりする前に、担当を交代するか外してください。そのままでは保存しません。
- 優先連絡先には電話番号が必要です（本人なら本人電話、キーパーソンなら氏名・続柄・電話、施設・その他なら優先連絡先の電話）。
- 保存は読み込んだ版に対してだけ行います。ほかの人が先に更新していたら保存せず、入力を残したまま知らせます。
- 薬局の患者と MCS の患者は、人が選んだときだけ1対1で対応付けます。氏名が完全に一致する MCS の患者は候補として出しますが、自動では対応付けません。対応付けと解除の履歴は消えません。
- 対応付けた患者は、MCS の画面の見出しに「台帳: 氏名」の札を表示し（押すと台帳のその患者を開きます）、台帳の画面から MCS のタイムラインを開けます。対応付けられるのは起動時に許可した患者範囲の中だけです。

### 患者台帳・訪問予定・職員の画面

- 「患者台帳」では、左の一覧（スマホでは「患者」ボタンの一覧）から患者を選びます。一覧の各行には、フリガナ、次の予定の日（「次 11/25」のような札）、MCS の患者と対応付けてあれば「MCS あり」、休止・終了の札が出ます。「＋ 患者を登録」で新しい患者を登録します。
- 患者を開くと、まず読むための画面「訪問時の情報」が出ます。見出しの右のタブ「訪問時の情報」「台帳を編集」で切り替えます。
- 「台帳を編集」では、基本情報（本人・連絡先・訪問先・利用状態）、ケアチーム、訪問、処方、MCS の患者の節を、上のボタンで移動しながら編集します。
- 「訪問予定」では、日ごとの訪問をカードで見ます（下の「訪問と処方」を参照）。「職員」では、職員を表で見て、行を開いて編集します。列は氏名・資格・管理者・Tailscale のログイン名・在籍です。「＋ 職員を追加」で登録します。

### 訪問と処方

- 患者の「台帳を編集」の「訪問」で、「＋ 訪問を予定する」から訪問を予定し、実施・中止を記録します。種類はモジュールが決めます（薬局なら「訪問薬剤管理」「配薬のみ」）。実施にするときは訪問した職員が必要です。訪問を別の患者へ付け替えることはできません。
- 薬局モジュールの「処方」（「＋ 処方を登録する」）で、処方日・医療機関・処方医と薬剤（名前・用量・用法・日数）を記録します。薬剤は入力した名前をそのまま残すので、薬剤マスターが更新されても過去の処方の表示は変わりません。薬剤名の一部を入れて「マスターから選ぶ」を押すと、承認済みの薬剤マスター（`drug_map`）から候補を選べ、その公式コードも一緒に保存します。薬剤マスターが未設定・未承認のときは候補が出ないので、薬剤名だけで登録します。選んだ後に薬剤名を書き換えると、コードは保存されません。
- 患者を開いたときに最初に出る「訪問時の情報」で、注意事項（あれば最上段）、連絡と訪問先（住所・優先連絡先・アクセス）、訪問（次の予定と最近の実施）、ケアチーム、最近の処方、MCS のやりとり（タイムラインへの入口）を、カードに分けて1画面で見られます。広い画面ではカードを複数列に並べます。MCS の患者と対応付けてあれば、公開スナップショットから「訪問前の確認」「前回から変わったこと」「患者背景」「返信待ち」と未解消のシグナルも同じ画面に出します。「前回から変わったこと」は最後に実施した訪問（開始時刻がなければその日の0時）からの変化で、実施済みの訪問がなければ直近7日の変化です。「訪問前の確認」などの記録の節に8件を超える記録があるときは、節ごとの「次のページ」で同じスナップショット・同じ基準のまま続きを開けます（スナップショットが更新されていれば読み直しを求めます）。未解消のシグナルは新しい順に50件までをまとめて表示し、続きはタイムラインの画面で確認します。
- 「訪問予定」で、日付ごとの訪問をカードで見られます。上の「◀ 前日」「今日」「翌日 ▶」と日付の入力で日を移し、その下の7日分の帯で、選んだ日から7日間の予定・実施の件数（中止があれば中止も）を見て、押した日へ移れます。帯の件数が読み込めないときは、その旨を表示します。
- 日の一覧の上には、予定・実施（あれば中止）の件数の札があります。職員が2人以上いるときは、「全員」と各職員の札で表示を絞れます。絞っても件数は絞った分で数え直すだけで、登録の内容は変わりません。
- 訪問のカードは時刻順で、時刻（決まっていなければ「時刻未定」）、患者名、種類、状態の札、担当、住所・施設、注意事項（あれば「⚠」の1行）、記録の先頭を表示します。カードを押すと、その患者の「訪問時の情報」を開きます。

### 訪問ルート（任意・外部送信あり）

`--route-settings` に設定ファイルを指定すると、「訪問予定」の画面のルートの欄で、その日の予定の訪問を回る順番と到着の目安を作れます。
**この機能は患者の住所を外部のサービスへ送ります。** 送るのは「ルートを作る」を押したときだけで、送る内容は次の2つです。

- 住所の文字列を国土地理院の住所検索（`msearch.gsi.go.jp`）へ送り、緯度・経度に変えます。変換した位置は台帳に保存し、住所が変わるまで同じ住所は送りません。
- 出発地と訪問先の緯度・経度、時刻を決めた訪問の時刻の幅を openrouteservice（`api.openrouteservice.org`）へ送り、道路に沿って回る順番を受け取ります。訪問は送るたびに振る通し番号で区別し、台帳の ID は送りません。

氏名・ID・電話番号・注意事項・メモは送りません。時刻を決めた訪問には、その前後15分に着く順番だけを作ります。間に合わない訪問は順番に入れず、件数を別に表示します。
住所から場所が分からなかった訪問と、検索結果が離れた複数の場所にまたがる住所（番地のない「中央区」など）は、推測で順番に入れず、件数を別に表示します。
結果は番号つきの一覧で、左に到着（訪問を始められる）見込みの時刻、右に患者名を表示します。幅1024px以上の画面では日の一覧の右、それより狭い画面では下にルートの欄が出ます。
設定ファイルの `depart_time`（`HH:MM`、省略時は `09:00`）を出発時刻として、訪問を始められる見込みの時刻を表示します。予定の時刻より早く着く場合は、その時間枠が始まる時刻を出します。
設定ファイルは所有者だけが読める JSON（`chmod 600`）で、openrouteservice の無料キーと出発地（事業所）の住所を書きます。

```json
{"openrouteservice_key": "（取得したキー）", "origin_address": "（事業所の住所）", "depart_time": "09:00"}
```

キーは openrouteservice のサイトで無料のアカウントを作って発行します。無料枠には1日あたりの回数の上限があります。

## スマホから使う（常駐モード）

1台の Mac で1つの事業所を扱います。Mac mini 以外の端末（スマホなど）から使う場合だけ、Mac と職員のスマホを同じ Tailscale の tailnet に入れます。

### インストーラーで設定する（推奨）

1. 導入時に `install.sh --with-tailscale`（または `mcs install --with-tailscale`）を実行します。段階1で Tailscale アプリ（Homebrew の `tailscale-app`）を入れます。この選択は保存され、後の更新・再導入でも引き継ぎます。`--with-tailscale` を付けない Mac には入れません。
2. Tailscale アプリを開き、事業所の Tailscale アカウントでサインインします。管理画面で MagicDNS と HTTPS 証明書を有効にします。
3. `mcs setup remote` を実行します。この Mac の Tailscale の名前を確かめて設定に保存し、`tailscale serve --bg http://127.0.0.1:8770` で tailnet に公開し、患者画面を常駐サービス（`ai.mcs.local-chat`）として登録します。公開するのは、その番号でこの常駐サーバーが応答することを確かめてからです。確かめられないとき（常駐サービスがまだ起動していない、別のプログラムがその番号を使っているなど）は公開せずに止まるので、`mcs setup check` で状態を確かめてから再実行します。患者は公開スナップショットの全員、台帳は `data/homecare.db` です。待ち受けの番号は `--port`、訪問ルートの設定ファイルは `--route-settings` で指定できます。公開スナップショットがまだ作られていない間は常駐サービスが起動に失敗し、30秒ごとに起動し直します。その間は `mcs setup remote` も公開せずに止まるので、公開スナップショットが作られてから再実行します。
4. スマホにも Tailscale を入れて同じアカウントでサインインし、表示された `https://<名前>.<tailnet>.ts.net/` を開きます。

やめるときは `mcs setup remote --off` で常駐サービスを止め、`tailscale serve status` を確かめてから `tailscale serve reset` で公開を止めます。

### 手で起動する

Mac の名前（`<名前>.<tailnet>.ts.net`）を確かめてから、固定のポートで起動します。例の `example-mac.example-tailnet.ts.net` は、この Mac の Tailscale の名前に置き換えてください。

```sh
python3 mcs/ops/mcs_local_chat.py \
  --snapshot /path/to/mcs/data/snapshots/ledger-snapshot.db --all-patients \
  --homecare-db /path/to/mcs/data/homecare.db \
  --port 8770 --tailnet-host example-mac.example-tailnet.ts.net
```

サーバーは起動した端末で動き続けます。別の端末で次を一度だけ実行し、tailnet へ公開します（`--bg` の設定は Mac を再起動しても残ります）。

```sh
tailscale serve --bg http://127.0.0.1:8770
```

- `tailscale serve` は tailnet の中だけに HTTPS で公開します。`tailscale funnel` は一般のインターネットに公開するので使いません。
- 職員はスマホのブラウザで `https://<名前>.<tailnet>.ts.net/` を開きます。秘密の URL はなく、Tailscale のログインで誰かを見分けます。
- スマホ（幅700px未満）では、上に「患者」ボタンと画面名・患者名・「更新」が並び、画面の下に「MCS」「患者台帳」「訪問予定」「職員」のタブバーが固定されます。左の患者一覧は出ません。「患者」ボタンで、検索欄・患者一覧・操作者を含む一覧が全画面で開き、患者を選ぶか「閉じる」で戻ります。患者台帳で患者を選ぶ前の画面にも「患者の一覧を開く」ボタンがあります。
- スマホでは本文を1列で表示し、投稿の詳細は全画面で開きます。文字は本文14px・補足12px以上で、入力欄に触れても画面が拡大しません。
- 職員として登録した Tailscale のログイン名（職員の画面の「Tailscale のログイン名」）と一致し、在籍中の職員だけが使えます。登録のないログインには、MCS の記録も台帳も表示しません。
- 職員がまだ1人もいないときだけ、最初に開いた人が自分を登録できます。その人の Tailscale のログインが結び付き、管理者になります。続く職員は管理者が登録し、各自のログイン名を入れます。
- 管理者は、まだ登録していない自分のログイン名を登録できます。登録済みのログイン名を自分で変えたり消したりはできません（次から自分で開けなくなるため）。変えるときは、別の管理者に頼んでください。
- すでに職員を登録した台帳を常駐モードで開くときは、先に通常の起動で、在籍中の管理者に Tailscale のログイン名を登録しておきます。登録しないまま常駐モードにすると誰も使えないので、通常の起動に戻ってログイン名を登録してから、もう一度常駐モードにします。
- tag を付けた端末からのアクセスには Tailscale がログインを付けないため、使えません。
- 同じ Mac の別のプロセスはログインを偽れるので、Mac は単一ユーザーで運用してください。

## 外部チャット表示との対応範囲

比較対象は `adapters/{slack,discord,lineworks}/cards.py` と、共通の `notify_render`・`structured_view`・`adapters/common/context_view.py`・`summary.py` です。
本機能は閲覧の入口をローカルへ追加するもので、外部チャットの全表示を完全に置換するリリースではありません。

| 既存画面に表示される内容 | ローカル画面 |
| --- | --- |
| 患者名・投稿者・職種・所属・投稿日時・原文・返信 | 対応。患者範囲をサーバー側で毎回検証 |
| 投稿ごとの要約、薬剤・バイタル・依頼など | 対応。通知と同じ有効性・削除・患者スコープ判定の `structured_lines` を再利用 |
| 投稿のスタンプ件数・取得状態・押した人 | 対応。すべての投稿で押した人の名前を表示（自分の投稿は自分以外のみ）。押した人の一覧が古い・取得失敗・未取得のときは明示。押した人の氏名は取得済みの範囲のみ |
| メンション・しおり・ピン留め | 対応。自分宛てメンション・ピン留め・ブックマークは観測できたものを投稿の札に表示し、未取得・不正な状態は詳細で表示。変更不可 |
| 緊急度・投稿ごとの要約の状態・最新返信 | 対応。緊急度の札と根拠、「要約 処理待ち」「要約 作成失敗」、最新の返信を投稿の行に表示 |
| 投稿の編集・削除の観測 | 対応。「変更を検知」「削除を観測」と取得側の観測時刻を表示。投稿者の編集時刻・変更前の本文は表示しない |
| 投稿に紐づく構造化背景情報 | 詳細で原文に結び付いた有効な項目・属性を表示 |
| 添付の名前・取得状態・OCR文字記録 | 対応。ファイルの状態と理由・大きさ・OCRの状態（失敗・未対応形式・除外を含む）・ページごとの文字記録を表示。署名URL・ローカルパス・ファイル配信なし |
| 添付PDF・画像の閲覧／ダウンロード | **未対応**。本機能から原本を開かない |
| 患者全体の26分類の背景情報 | 見出しの下で既存background投影を表示（アレルギーが先頭）。全分類の記録と根拠を展開可能。未取得は空欄として明示 |
| 患者の施設・病名・取得状態・MCSへのリンク | 対応。見出しに施設名・病名・取得状態と理由・最終取得・初回取込・「MCSで開く」を表示 |
| 連携サマリー（MCS患者連携サマリー） | 対応。全文・更新日時・更新した職種、未取得・取得失敗・空の区別を表示 |
| MCSの患者情報の登録データ（薬剤登録・観測項目・観測値） | 対応。「MCS登録データ」タブに取得状態つきで表示（先頭200件まで）。ケアチームの氏名は表示しない |
| 原資料（投稿本文・添付OCR）の検索 | 対応。選択中の患者だけを検索し、検索しなかった範囲を表示。投稿者名では検索しない |
| 患者全体の経過／訪問前確認・変化・食い違い・引継ぎなどの画面 | 対応。表示タブから通知カードと同じ投影を表示。測定値の原文記録（Slackのみ）は未対応 |
| 投稿ごとの薬剤（💊） | 対応。投稿の詳細から表示 |
| 未解消のシグナル・返答確認の件数 | 対応。種別・内容・検出時刻と根拠の投稿に加え、見出しの札で件数と判定中・取得できないを区別 |
| 未完了タスク・患者単位の抽出の処理状況 | 対応。「記録のまとめ」に表示 |
| 横断サマリー・薬剤辞書の検索・処理プロバイダー進捗 | **未対応**。既存ローカルCLI／外部チャット表示を継続 |
| 確認者・担当者・誤り報告・配送／取り下げ状況 | **未対応**。通知カード固有の状態はこの画面では表示しない |
| 送信・既読化・スタンプ・承認操作・予定配信 | 対象外。書込み経路や定期処理を追加しない |

## データ境界

既存の `View` / `LedgerReader(mode=ro)` が検証した公開スナップショットだけを読みます。
患者データはHTMLへ埋め込まず、同一オリジンの秘密URL以下から読み込み、DOMの `textContent` で表示します。
ブラウザへの応答は `no-store`、外部リソース・フレーム・フォーム送信はCSPで遮断し、アクセスログへURLや検索語を出力しません。
起動ごとの秘密URLと厳密なHost・Origin・Fetch Metadata検証で、別サイトからの読取りやDNS rebindingを拒否します。
ブラウザ履歴や画面には患者情報が残り得ます。共有ブラウザを使わず、閲覧後はタブとサーバーを閉じてください。
薬局の患者台帳への書込みは、同一オリジンからの `fetch` だけを受け付けます。Origin ヘッダー（`Sec-Fetch-Site` を送るブラウザでは、その値が `same-origin` であること）、起動ごとに変わる書込み用の値（`X-MCS-CSRF`）、`application/json`、64KiB 以下の本文がそろわない要求は保存しません。
エラーは固定の符号だけを返し、入力値や患者情報を含めません。
訪問ルートを設定した場合だけ、上の「訪問ルート」に書いた住所と位置を、固定の2つの宛先へ HTTPS で送ります（proxy 無効・redirect 拒否）。
