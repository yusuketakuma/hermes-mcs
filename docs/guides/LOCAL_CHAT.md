# ローカル患者タイムライン

患者をチャンネルとして選び、保存済みの投稿を古い順に閲覧するSlack風の画面です。
外部チャットのアカウント・SDK・CDN・クラウド推論は不要です。macOSのローカル操作者が明示的に起動する閲覧専用機能（薬局の患者台帳を指定したときだけ台帳を編集できます）で、既存のSlack・Discord・LINE WORKS連携は残します。

## 起動

導入先のPython環境で、公開済みスナップショットと閲覧を許可する患者IDを指定します。
原本の `ledger.db` は指定できません。スナップショットを外部へコピーしないでください。

```sh
python3 mcs/ops/mcs_local_chat.py \
  --snapshot /path/to/mcs/data/snapshots/ledger-snapshot.db \
  --project 101 --project 102
```

表示された秘密URLを**同じMacのブラウザ**で開きます。URLを共有・外部チャットへ投稿しないでください。
ポートは空き番号を自動選択します。固定する場合は `--port 8765`。終了は `Ctrl+C` です。
全患者を表示する権限を持つローカル操作者だけが `--project` の代わりに `--all-patients` を指定できます。
患者範囲の指定なしでは起動しません。この指定は既存の外部チャット利用者の権限を継承・拡張するものではありません。

自動起動・インストール・外部公開・LANアクセス・リバースプロキシは追加しません。
OSアカウントへのアクセス権を持つローカル操作者向けです。共有端末の利用者別認証や遠隔アクセス用ではありません。

## 使い方

- 左の患者一覧を選択。患者名・IDで絞り込めます。
- 患者名の右に、その患者の保存済みコンテキストを表示します。「背景・根拠をすべて表示」で分類別の記録・対象者・日付・根拠を確認できます。狭い画面では患者名の下に表示します。
- 本文・投稿者の検索は選択中の患者だけを対象にし、返信も検索します。
- 通常は直近50件の親投稿を古い順で表示。「以前の投稿」で過去へ進みます。
- 「詳細・返信」で元投稿・返信・メンション等の状態・構造化記録・添付を表示します。
- 「記録の要約」は既存通知と同じ `structured_view.structured_lines` の有効な投影です。
- 添付は取得状態と保存済みのOCR文字記録のみ。PDFや画像の原本は配信しません。
- 検索欄の左の「表示する内容」で、タイムラインのほかに患者別の画面を選べます。記録のまとめ（未完了タスク・抽出の処理状況を含む）、患者さんの全体像、前回から変わったこと、連絡・返答の確認、訪問前の確認ノート、経過タイムライン、出来事・検査・観測の記録、記録の食い違い、引継ぎ用の記録、退院・移行時の経過、未解消のシグナルです。中身は通知カードの同名の画面と同じ `notify_views` の投影です。
- 「前回から変わったこと」は閲覧の記録を残さないため、毎回直近7日を基準に表示します。「直近」「今後」などの期間は、閲覧した時刻ではなくスナップショットを作った時刻を基準にします。
- 未解消のシグナルは、すべての種類の判定が終わったことを確認できないときはその旨を表示し、該当がなくても「ありません」とは断定しません。
- 投稿の詳細の「この投稿の薬剤を表示」で、通知カードの💊と同じ薬剤の一覧を表示します。返信の薬剤は、返信の「添付・記録の状態」から開く「この返信の薬剤を表示」で確認します。一覧に出る「誤りを報告」の案内は通知カードの操作で、この画面からは報告できません。
- 「更新」は公開スナップショットを読み直します。自動取得・新しい解析は行いません。

時刻はJSTの投稿時刻です。本文に書かれた出来事の日付を並び順へ読み替えません。
複数行のコンテキストは、後続の本文がすべて同じ分類とは限りません。明示的な見出し行と、分類範囲を確認できない原文全体を分けて表示します。続きや但し書きは削除せず、原文全体から確認できます。対象者や現在の状態は推測しません。
本文や返信の未取得・履歴全体の取得未確認を明示します。検索結果なしは対応なしを意味しません。
公開スナップショットが置換された場合、古いページ送りは拒否されます。「更新」で読み直してください。

## 在宅ケアの患者台帳（任意）

`--homecare-db` を付けて起動すると、MCS とは別に事業所の患者台帳と職員の名簿を同じ画面で扱えます。
在宅業務の記録（旧 zaitaku-calender の機能）をこのMacへ移すための土台で、職種に共通の機能（コア）の上に職種別のモジュールを載せる作りです。今は薬局モジュールだけがあり、`--homecare-module pharmacy`（既定）で有効になります。指定しなければ、これまでどおり閲覧専用です。

```sh
python3 mcs/ops/mcs_local_chat.py \
  --snapshot /path/to/mcs/data/snapshots/ledger-snapshot.db --all-patients \
  --homecare-db /path/to/mcs/data/homecare.db
```

- 台帳のファイルは初回に作られます（ファイル 0600・フォルダ 0700）。原本の `ledger.db` とスナップショットには書き込みません。
- 左上の切替で「MCS」「薬局の患者」「職員」を選びます。初回は職員の画面が開くので、まず自分を登録します。最初の1人だけは操作者なしで登録でき、その人がそのまま操作者と管理者になります。
- 職員には資格（事務・その他と、有効なモジュールの資格。薬局なら薬剤師）を1つ以上付けます。職員の登録と変更は管理者だけができ、自分自身を退職や管理者以外に変えることはできません。
- 患者ごとの「ケアチーム」で、この事業所の担当者を役割ごとに決めます。薬局モジュールの役割は「担当薬剤師」で、薬剤師の資格を持つ在籍中の職員だけを選べます。別の人を担当にすると前の担当は外れ、交代の履歴が残ります。
- 2件目以降の登録・変更は、左の「操作者」で選んだ在籍中の職員の名前で記録します。誰がいつ何をどう変えたかを、変更前と変更後の両方で残します。
- 優先連絡先には電話番号が必要です（本人なら本人電話、キーパーソンなら氏名・続柄・電話、施設・その他なら優先連絡先の電話）。
- 保存は読み込んだ版に対してだけ行います。ほかの人が先に更新していたら保存せず、入力を残したまま知らせます。
- 薬局の患者と MCS の患者は、人が選んだときだけ1対1で対応付けます。氏名が完全に一致する MCS の患者は候補として出しますが、自動では対応付けません。対応付けと解除の履歴は消えません。
- 対応付けた患者は、MCS の画面の患者名の下に台帳の氏名を表示し、台帳の画面から MCS のタイムラインを開けます。対応付けられるのは起動時に許可した患者範囲の中だけです。

## 完全合成デモ

実患者・匿名化した実投稿は使いません。次のコマンドは新規ディレクトリだけに完全合成データを作ります。

```sh
python3 scripts/development/local_chat_demo.py --output /path/to/new-synthetic-demo
python3 mcs/ops/mcs_local_chat.py \
  --snapshot /path/to/new-synthetic-demo/snapshots/ledger-snapshot.db \
  --all-patients
```

## 外部チャット表示との対応範囲

比較対象は `adapters/{slack,discord,lineworks}/cards.py` と、共通の `notify_render`・`structured_view`・`adapters/common/context_view.py`・`summary.py` です。
本機能は閲覧の入口をローカルへ追加するもので、外部チャットの全表示を完全に置換するリリースではありません。

| 既存画面に表示される内容 | ローカル画面 |
| --- | --- |
| 患者名・投稿者・職種・所属・投稿日時・原文・返信 | 対応。患者範囲をサーバー側で毎回検証 |
| 投稿ごとの要約、薬剤・バイタル・依頼など | 対応。通知と同じ有効性・削除・患者スコープ判定の `structured_lines` を再利用 |
| 投稿のスタンプ件数・取得状態・押した人 | 既存evidence投影と共通フォーマッターで表示。投影が許す範囲の氏名のみ |
| メンション・しおり・ピン留め | 詳細で取得状態を表示。変更不可 |
| 投稿に紐づく構造化背景情報 | 詳細で原文に結び付いた有効な項目・属性を表示 |
| 添付の名前・取得状態・OCR文字記録 | 対応。署名URL・ローカルパス・ファイル配信なし |
| 添付PDF・画像の閲覧／ダウンロード | **未対応**。本機能から原本を開かない |
| 患者全体の26分類の背景情報 | 患者名の右で既存background投影を表示。全分類の記録と根拠を展開可能。未取得は空欄として明示 |
| 患者全体の経過／訪問前確認・変化・食い違い・引継ぎなどの画面 | 対応。「表示する内容」から通知カードと同じ投影を表示。測定値の原文記録（Slackのみ）は未対応 |
| 投稿ごとの薬剤（💊） | 対応。投稿の詳細から表示 |
| 未解消のシグナル | 対応。種別・内容・検出時刻と根拠の投稿 |
| 未完了タスク・患者単位の抽出の処理状況 | 対応。「記録のまとめ」に表示 |
| 横断サマリー・薬剤辞書の検索・処理プロバイダー進捗 | **未対応**。既存ローカルCLI／外部チャット表示を継続 |
| 確認者・担当者・誤り報告・配送／取り下げ状況 | **未対応**。通知カード固有の状態はこの画面では表示しない |
| 送信・既読化・スタンプ・承認操作・予定配信 | 対象外。書込み経路や定期処理を追加しない |

## データ境界

既存の `View` / `LedgerReader(mode=ro)` が検証した公開スナップショットだけを読みます。
患者データはHTMLへ埋め込まず、同一オリジンの秘密URL以下から読み込み、DOMの `textContent` で表示します。
ブラウザへの応答は `no-store`、外部リソース・フレーム・フォーム送信はCSPで遮断し、アクセスログへURLや検索語を出力しません。
起動ごとの秘密URLと厳密なHost・Origin・Fetch Metadata検証で、別サイトからの読取りやDNS rebindingを拒否します。
ブラウザ履歴や画面には患者情報が残り得ます。共有ブラウザを使わず、閲覧後はタブとサーバーを閉じてください。
薬局の患者台帳への書込みは、同一オリジンからの `fetch` だけを受け付けます。Origin ヘッダーと `Sec-Fetch-Site: same-origin`、起動ごとに変わる書込み用の値（`X-MCS-CSRF`）、`application/json`、64KiB 以下の本文がそろわない要求は保存しません。
エラーは固定の符号だけを返し、入力値や患者情報を含めません。
