# 失敗ジョブの調査と再試行

`mcs jobs failed` は、失敗した解析ジョブの理由、確認すべき対策、再試行を止めている条件を表示します。本文や認証情報は表示せず、ジョブを変更しません。一覧は既定50件、最大100件です。個別に調べる場合は `mcs jobs failed --job-id 123` を使います。

失敗理由は、同じジョブ・入力世代・本文条件・試行回数に結び付いた実行記録から確認します。記録が古い、または不足している場合は `unknown` と表示します。原因を推測で補いません。

表示された対策を実施してから、一覧の `diagnosis_hash`、`expected_payload_hash`、`remediation_code` を指定します。次は形式の例です。数値とハッシュは実際の診断結果に置き換えてください。

```sh
mcs jobs retry --job-id 123 \
  --diagnosis-hash <診断ハッシュ> \
  --expected-payload-hash <入力ハッシュ> \
  --remediation budget \
  --additional-attempts 1 \
  --confirm-human --reason '失敗原因と実施した対策'
```

`--additional-attempts` は、試行上限に達したジョブに限り、追加する試行回数を1〜3回で指定します。上限に達していないジョブでは省略してください。累積試行回数や入力世代は消しません。再試行は予約され、実際の処理は通常のワーカーが費用上限や対象範囲を確認して行います。

理由が `unknown` の場合は、ローカルで原因と対策を調査し、`--remediation investigate` と確認理由を指定します。理由や調査結果に患者情報、投稿本文、秘密値を含めないでください。旧世代のジョブ、取得不足、処理保留、送信結果が不明なクラウド要求などの阻害条件は、この操作では解除できません。

再試行の直前に診断を照合します。本文・解析対象範囲・ジョブの状態が変わった場合は拒否されるため、再度調査してください。操作には確認理由を含む受領記録が残ります。結果が不明な操作を確認する場合は、同じ引数と `--command-id` のUUIDを再利用してください。同じ操作は重複して予約されません。
