# 保存済み添付の整合を点検する

この手順は、ローカルの運用者が、DBで`downloaded`になっている添付の実ファイルを読取り専用で点検し、再取得の候補を整理するためのものです。DB・ファイルの変更、再取得、再送、既読化、自動修復は行いません。

## 1. 点検する

公開snapshotと添付ディレクトリを明示して実行します。設定からの自動探索はしません。

導入時に選択したMCS用Pythonの絶対パスを`PY`に指定してください。macOS標準の`python3`とは区別します（[導入ガイド](INSTALLATION.md)）。

```sh
PY=/absolute/path/to/mcs-python
"$PY" mcs/ops/mcs_repair.py attachments \
  --snapshot /absolute/path/ledger-snapshot.db \
  --attachment-root /absolute/path/data/attachments \
  --out /absolute/private-dir/attachments-audit.json
```

- snapshotは稼働DBではなく、`-wal`・`-shm`・`-journal`のない静的なファイルを指定します。開始時と終了時のSHA256が変われば拒否します。
- 添付ディレクトリは`/`から1階層ずつsymlinkをたどらずに開きます。途中のどこかがsymlinkの場合や開けない場合は全体を拒否し、その時は1件も`missing`にしません。
- `--out`は本人だけが読める既存ディレクトリ（`0700`）の中の、まだ存在しないファイル名を指定します。結果は`0600`で作成し、既存ファイルは上書きしません。

標準出力には件数と固定の理由だけを出します。添付ID・投稿ID・続きの位置は`--out`の私有ファイルにだけ書きます。

## 2. 結果を読む

点検対象は`state='downloaded'`の行だけです。各行に次のいずれかの理由が付きます。

| 理由 | 意味 | 区分 |
|---|---|---|
| `missing` | 指定ディレクトリの中にファイルがないことを確認した | 再取得候補 |
| `size_mismatch` | ファイルサイズが記録された`bytes`と違う | 再取得候補 |
| `unreadable` | 権限・I/Oエラーで開けない、または読めない | 再取得候補 |
| `not_regular` | symlink・FIFO・ディレクトリなど通常ファイルではない。開かずに止める | 人が確認 |
| `path_mismatch` | 記録された`local_path`が指定ディレクトリ直下の`<attachment_id>`ではない。開かずに止める | 人が確認 |
| `record_invalid` | `bytes`や`local_path`の記録が欠けている・不正 | 人が確認 |

サイズと読取り可否で判定し、内容のSHA256は比較しません。サイズが同じで中身だけ壊れた添付は検出しません。

## 3. 上限と中断

- 点検は`--limit`（既定1000、最大100000）件で止まります。
- `--max-seconds`（既定30、最大3600）秒は、DBの検索とファイル点検の合計に適用します。開始時と終了時のsnapshotのSHA256計算にも、それぞれ同じ秒数を別に適用します。全体では最大でおよそ3倍の時間がかかります。
- SHA256計算が上限を超えた場合は、snapshotが変わっていないことを確認できないため、結果全体を拒否します。
- DBの検索やファイル点検の途中で上限に達した場合は`partial: true`と`stop_reason`（`limit`または`time`）を返し、未点検の件数を`unchecked`に出します。件数を数える前に止まった場合、`unchecked`は`null`（不明）です。0件とは扱いません。未点検の行は欠損とは扱いません。
- 時刻の確認は読取りや検索の合間に行います。1回の読取りやファイルを開く処理そのものは途中で止められないため、遅いディスクでは上限を少し超えることがあります。
- 続きは、私有ファイルの`next_after_id`を`--after-id`に渡して再実行します。実行ごとに、その時点のsnapshotで結果を作り直します。複数回の結果を合わせる時は、各結果の`snapshot_sha256`を確認してください。
- 定期処理には組み込んでいません。必要な時に手動で実行します。

## 4. 再取得の判断

私有ファイルの`plan.refetch`は再取得の候補、`plan.operator_review`は人が先に確認する候補です。収集処理は`downloaded`の行を再取得しないため、現時点で候補を再取得へ戻す対応経路はありません。再取得には所有者の判断と、別途承認された手順が必要です。この点検の結果だけでDBやファイルを書き換えないでください。
