# 医療情報システムとして使うための法令・ガイドライン対応

この文書は、薬局・訪問看護ステーション・診療所が hermes-mcs を業務で使うときに、
施設側で整えるべきことと、ソフトウェアが用意している機能を対応づけたものです。
**法的助言ではありません。** 実際の導入判断は、施設の顧問弁護士・個人情報保護の担当者、
必要に応じて都道府県の薬務担当や個人情報保護委員会の相談窓口に確認してください。

確認日は 2026-11-15 です。根拠資料は末尾の「出典」に一次資料の URL を挙げています。

## 1. まず押さえる前提

- hermes-mcs は施設の Mac に置く「医療情報システム」です。MCS の投稿・添付・患者名を複製して
  保存し、要約・通知に使います。厚生労働省の安全管理ガイドラインは、医療情報を保存・閲覧する
  端末やネットワークも医療情報システムに含めています（Q&A Q7）。
- 扱う情報の多くは病歴等を含む**要配慮個人情報**です（個人情報保護法 第2条第3項）。
- 薬剤師・医師には刑法第134条、看護師には保健師助産師看護師法第42条の2の守秘義務があります。
  外部サービスへの送信は「正当な理由」と施設の手続を説明できる状態で行います。
- 次の4つはコードでは解決できません。導入前に施設（または販売者）が確認します。

| 確認事項 | 誰が | 理由 |
|---|---|---|
| MCS 運営会社の書面での許諾 | 販売者・施設 | 確認できた MCS 契約者規約（令和3年8月版）第5条は、患者情報の複製・外部への持出しと、許諾範囲を越えた提供を禁じています。現行規約の本文は未確認です |
| 外部AI・通知サービスとの契約条件 | 施設 | 学習に使わない・保存しないことが契約で担保されているか（安全管理GL Q&A Q18）。外国にある事業者への提供の根拠（個人情報保護法 第28条） |
| 患者・利用者への周知と同意 | 施設 | 利用目的の掲示、外国の事業者へ送る場合の同意または体制整備の確認 |
| 医療機器プログラムに当たらないことの確認 | 販売者 | 販売時の説明や機能追加で使用目的が変わると判断も変わります（6章） |

## 2. 責任分界表

安全管理ガイドライン第7.0版（システム運用編3章・企画管理編）は、医療機関等と事業者の責任分界を
文書で合意することを求めています。下表は既定の分担案です。契約時に施設と販売者で確定してください。

| 項目 | 施設（医療機関・薬局等） | hermes-mcs の提供者 | MCS 運営会社 | 通知先・外部AIの事業者 |
|---|---|---|---|---|
| 安全管理責任者の設置・運用管理規程 | ◎ | 規程ひな形の提供 | － | － |
| Mac の管理（FileVault・OS更新・画面ロック・利用者アカウント） | ◎ | 設定手順の提供 | － | － |
| MCS アカウントの管理・利用規約の遵守 | ◎ | 収集間隔などの負荷配慮 | 規約・認証 | － |
| 収集・保存・既読化の安全ゲート | 設定 | ◎（ソフトウェア） | － | － |
| 通知チャンネルの参加者管理 | ◎ | 送信先を限定する設定 | － | 各サービスの認証・保存 |
| `/mcs` 利用者と患者範囲の許可 | ◎（`allowed_user_ids`・`project_ids`） | 許可の強制と閲覧記録 | － | － |
| 閲覧・操作記録の定期確認 | ◎ | 記録・改ざん検査・集計の機能 | － | － |
| 外部AIへの送信可否の判断 | ◎（確認記録） | 確認記録がない新規導入では自動送信しない | － | 契約上の保存・学習条件 |
| バックアップ・BCP | ◎ | 暗号化 offsite と復元の機能（[BACKUP.md](BACKUP.md)） | － | － |
| 保守・遠隔支援 | 承認・作業記録の確認 | 同意済みの範囲だけで作業し報告 | － | － |
| 事故時の報告（個人情報保護委員会・本人） | ◎ | 調査への協力・記録の提供 | － | － |

## 3. 患者情報の行き先

| 送信先 | 送るもの | 所在 | 既定 | 止め方 |
|---|---|---|---|---|
| MCS（取得元） | 既読化・スタンプ操作 | 日本 | 設定時 | `stamps.enabled=false` など |
| Slack / Discord | 本文・要約・添付・患者名 | 米国の事業者 | 設定した場合 | 通知先を設定しない |
| LINE WORKS | 本文・要約・患者名 | 日本の事業者（契約で確認） | 設定した場合 | 独立アダプターを停止 |
| Anthropic / OpenAI | 本文・患者文脈（患者名を含み得る。匿名化しない） | 米国の事業者 | 既存環境はキーで自動。新規導入は確認記録の後 | `cloud_llm.mode=off` |
| TypeSafe Jev | 確認用の設問と本文 | 契約で確認 | 既存環境はキーで自動。新規導入は確認記録の後 | `semantic.mode=off` |
| Exa / TinyFish（医薬品情報） | 公開マスターと一致した薬品名・一般的な疾患語のみ | 米国ほか | 有効 | 患者情報は送りません |

Slack・Discord・米国の AI 事業者は「外国にある第三者」に当たり得ます。米国は個人情報保護委員会規則で
定める同等水準の国ではないため、本人の同意か、契約等による基準適合体制（規則第16条）の整備が必要です。
医療・介護関係事業者ガイダンス（令和8年4月改正）10章も同じ整理です。どちらで対応するかは弁護士と決めてください。

## 4. 外部AI送信の施設確認（新規導入）

新しく導入した環境は `~/.mcs/external_transfer.json` に「確認待ち」を記録し、APIキーを登録しても
Anthropic・OpenAI・Jev へ自動では送りません。次を確認したうえで、責任者が記録します。

1. 送信先との契約で、入力が学習に使われず、保存期間と削除が定められていること
   （Anthropic の Zero Data Retention や OpenAI の保持条件は、組織ごとの契約が必要です。[ANTHROPIC.md](ANTHROPIC.md)）。
2. 外国にある第三者への提供の根拠（同意、または契約による体制整備）。
3. 患者・利用者への周知（[掲示文例](compliance/PATIENT_NOTICE_TEMPLATE.md)）。

```bash
python3 mcs/ops/mcs_compliance.py acknowledge --by "管理薬剤師 氏名" \
  --reason "2026-11-20 契約・同意書式・運用管理規程v1を確認" --services anthropic,jev --confirm-human
python3 mcs/ops/mcs_compliance.py status
```

記録は確認者・根拠・対象サービス・日時を残し、再確認したときは前回の記録を履歴に移します。
`config.json` で `mode` を明示した設定は、施設の判断として確認記録に関係なく従います。
既存の環境（このファイルが無い環境）はこれまでどおりキーで自動有効化するので、
同じ確認を済ませていない場合は `mode=off` を明示してください。

## 5. 閲覧・操作の記録（アクセスログ）

安全管理ガイドライン（システム運用編17章）は、利用者・時刻・操作した医療情報が分かるアクセスログと、
その改ざん防止・定期確認を求めています。医療・介護関係事業者ガイダンスも「アクセス記録の保存」と
「不正が疑われる異常な記録の定期的な確認」を挙げています。

- Slack・Discord・LINE WORKS の `/mcs` 操作は、回答の前に `~/.mcs/data/access_log/access-YYYY-MM.jsonl` へ
  利用者・チャンネル・操作・患者ID・結果を1行で残します。一覧の回答は、表示した患者のIDも残します
  （1行200人まで、超えた分は人数だけ）。サマリーも表示した患者のIDを残します。
  検索語・本文・患者名は残さず、操作・種類が定義済みの名前でない拒否された要求は `invalid` として残します。
- 記録できないときは閲覧の回答を返しません。確定済みの依頼・操作は別の受付記録があるため回答を返します。
- 各行は直前の行の SHA-256 を持ち、途中の行の削除・改変・月ファイルの欠落を検出できます。
  末尾の行の削除・改変は連鎖だけでは分からないため、`verify` が出す `records` と `head` を
  点検記録（端末の外）に書き、次回 `--checkpoint 件数:head` で照合します。

```bash
python3 mcs/ops/mcs_compliance.py access-log verify --checkpoint 1234:<前回のhead>  # 改ざん検査
python3 mcs/ops/mcs_compliance.py access-log review --days 30 # 利用者ごとの件数・患者数・拒否・夜間
python3 mcs/ops/mcs_compliance.py access-log show --project 123
```

月1回の確認と記録の保存期間は、運用管理規程で決めてください（自動削除はしません）。
次は記録の対象外です。運用管理規程の業務日誌で補ってください。

- Mac 上で `sqlite3` や `mcs_view.py` を直接使う操作（OS のアカウント管理と画面ロックで制御します）
- Slack・Discord に届いた通知の閲覧（各サービスの監査ログ。プランにより利用できません）
- カードのボタン操作（操作者付きの受付記録 `command_receipts` が残ります）

時刻は Mac の時計（UTC で記録）です。macOS の「日付と時刻を自動的に設定」を有効にしてください。

## 6. 医療機器プログラム（SaMD）に当たらないための位置づけ

厚生労働省「プログラムの医療機器該当性に関するガイドライン」（令和5年3月31日改正）は、
「医療関係者が患者の健康記録等を閲覧等するプログラム」と「医療関係者のオンラインでの
コミュニケーション・情報共有支援を目的とするプログラム」を医療機器に該当しない典型例に挙げています。
hermes-mcs の使用目的は次のとおりとし、販売資料もこれに合わせます。

> 本ソフトウェアは、多職種連携チャットの記録を保存・検索・整理し、確認や返信が必要な投稿を
> 医療・介護職に知らせる業務支援プログラムです。疾病の診断・治療・予防を目的とせず、医療機器ではありません。
> 表示される要約・候補は原文の確認を前提とし、臨床判断は医療・介護職が行います。

注意する点:

- 「至急」等の語による並べ替えや、`symptom_after_med_change`（薬の変更と症状が同じ投稿にある）の候補は、
  連絡の確認漏れを防ぐための表示です。**「副作用を検知する」「重症度を判定する」とは説明しない**でください。
  ガイドラインは、医療機器ではない旨の表示があっても、疾病の疑いを判断できると認識させる広告をすると
  医療機器に当たるとしています。
- 用量の計算・相互作用の判定・診断の候補表示などを加える前に、都道府県の薬務担当または PMDA の
  プログラム医療機器の相談で該当性を確認してください。
- 上の位置づけは README・販売資料・契約書に書きます。チャット表示には但し書きを付けない方針です
  （所有者の決定、2026-10-08）。

## 7. サイバーセキュリティ対策チェックリスト（令和8年度版）との対応

立入検査で確認される「医療機関・薬局確認用」の項目と、hermes-mcs が関わる部分です。

| 項目 | hermes-mcs の機能 | 施設が行うこと |
|---|---|---|
| 1① 安全管理責任者 | － | 任命し規程に記載 |
| 2① 機器の台帳 | － | Mac・通知先・外部サービスを台帳に記載（3章の表を使えます） |
| 2② 遠隔保守の有無 | 遠隔支援は同意がある場合だけ（`mcs support`） | 事業者に確認・記録 |
| 2③ MDS/SDS の提出 | 本書と[リスクアセスメント](compliance/RISK_ASSESSMENT.md)を開示資料の素案に使えます | 販売者から正式版を受領 |
| 2④ 職種・業務別のアクセス権限 | 利用者・チャンネル・患者範囲の許可リスト。**職種別の権限は未対応** | チャンネルを職種・担当で分け、許可リストを最小にする |
| 2⑤ 不要アカウントの削除 | 許可リストから外すと次の操作から拒否 | 退職・異動時に許可リストと通知チャンネルを更新 |
| 2⑥ セキュリティパッチ | 更新機能（`mcs update`） | macOS・Hermes・ブラウザを更新 |
| 2⑦⑧ パスワード | MCS パスワードは Keychain に保存 | 8桁以上（二要素認証までは13桁以上）、使い回し禁止 |
| 2⑪⑫ 二要素認証 | － | Mac のログインと Slack 等で二要素認証を有効化 |
| 2⑬ アクセスログ | 5章の閲覧記録 | 月1回確認し結果を記録 |
| 3② バックアップと復旧手順 | 日次 backup と暗号化 offsite（[BACKUP.md](BACKUP.md)） | 鍵の保管と復元訓練 |
| 3③ BCP | － | [運用管理規程ひな形](compliance/OPERATIONS_POLICY_TEMPLATE.md) 8章を使って策定 |
| 4① 規程類 | ひな形の提供 | 施設の実情に合わせて制定 |

## 9. まだ対応していないこと

- 職種・担当業務ごとの閲覧権限（現在は利用者・チャンネル・患者範囲の許可だけ）
- 外部AIへ送る前の患者名・識別子の仮名化（現在は匿名化しません）
- Mac 上の直接操作の記録、閲覧記録の外部への複製（改ざん検知はできますが、同じ端末の管理者は削除できます）
- 患者からの開示・利用停止請求（個人情報保護法 第33条以下）に応える患者単位の抽出・削除の手順
