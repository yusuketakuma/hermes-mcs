## 現行の提供・集約方針（2026-10-26）

- MCSの製品コード・文書・検証を`release/1.1.0`へ集約します。ワークツリーはブランチの作業場所であり、別の公開版ではありません。
- CSDCのコードと固定契約は同梱しますが、1.1.0では有効化・接続して提供しません。中央・実機の受入が整ってから接続を判断します。過去の「1.1.0で診断送信・遠隔支援を有効提供する」という必須条件を置き換えます。
- 新規導入の`sdc.enabled`は未設定で専用ジョブの登録対象外です。`optional_features.csdc`は案内の表示だけを決め、通信の停止設定ではありません。既存の有効設定・同意・資格情報を更新で自動停止・変更しません。
- 保存済みactive状態と現在の設定未指定・空・falseの組合せで送信へ進む問題を固定`51a06aef`で修正し、releaseへ統合しました。作者の合成390件成功を受領し、統合後の対象検証・独立レビューは別に記録します。実接続は未受入です。OFFを理由に実装回帰や安全検証を省略しません。
- CSDC中央API・管理画面・配布正本はCSDCリポジトリに所属します。MCS製品側のCSDC実装も担当はcsdcタブに集約し、MCSタブで二重実装しません。以下の初期担当表は現在の編集予約ではありません。
- 全体テストは担当Claudeの会話での個別承認に基づき実行中です。`864e4713`の1回目は300秒hangで中断、2回目は既知1件を除く診断用実行で、統合後releaseの全件合格ではありません。

## 決定と制約

- 初回設定で送信先/情報を確認し、登録コード・管理者承認・本人同意後に接続。正常な通信断のみ自動復帰、明示停止/失効/認証・順序異常は停止を保持。
- 未設定/拒否/停止でもMCS本体を継続。
- ユーザー直接指示により双方のエラー報告・遠隔復旧サポートを1.1.0へ含める。中央R4aと製品側の契約/署名/ローカル同意部品を実装・対象検証中。runtime接続/実機受入と有効化は未完。
- 既存CSDC R4a diagnostics.read、別受入R4b service.restart。R5更新/DB復元/R8SSH・画面共有は一括承認に含めず既存別承認を保持。
- 1.1.0からの外部利用は個別契約した顧客へ許諾。LICENSEとREADMEは方針を明示し、契約書の締結・利用者/導入先/用途の個別許諾は別に行う。
- 最初の顧客向け受入はmacOS・Apple silicon・Slackのstandaloneを優先する。既存Hermes/Discord/LINE WORKSの機能・互換性は維持し、実行方式の既定値変更や他方式の受入済みを意味しない。
- 所有者は1.1.0に診断送信・遠隔支援まで含めると選択。R3/R4の中央契約・署名/同意/receipt・障害回復を受入条件から外さず、未完成状態では有効化しない。R0→R1の先行順序とheartbeat送信専用契約を維持する。
- 所有者は問い合わせ・脆弱性報告の窓口を当面空欄にすると選択。メール/URL/対応時間を仮作成せず、窓口が実在するという受入は未完とする。
- CSDC本人回答: 中央がR2共通vectorとR3顧客/Keychain候補を所有、MCSはe541基点の固定patch/hash/試験結果受領後に独立レビュー。中央がR4 schema/vector初版、MCSが製品診断providerと既存操作ownerへの接続を所有。別cloneの同一ファイルを二重実装せず、本番/顧客有効化承認は追加しない。
