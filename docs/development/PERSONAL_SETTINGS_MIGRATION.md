# MCSの個人設定の集約

## 設定の保存先

MCS本体の個人設定は、導入先の `config.json` に集約する。このファイルはGit管理に含めない。初回インストール時にファイルがなければ本人専用のファイルを作成し、初期設定の完了とは区別する。保存済みの値は保持し、未指定の項目は各バージョンの実行時の既定値を使う。認証情報は設定値と分け、既存の保護された保存先を維持する。

Hermes固有の設定はHermes側で管理する。認証情報は、Hermes版とスタンドアロン版それぞれの既存の仕組みを維持する。接続先ごとの私有credential保存先や `.env` に加え、MCSログイン用に両方式が共通で利用するKeychain・環境変数などの参照順も変えない。Hermes profileの設定や資格情報を `config.json` へ移す必要はない。

新規導入では `config.json` の `provider_settings` にAnthropic・OpenAI・Jevの設定を保存する。費用上限はAnthropicとOpenAIの合計で1日80ドル・1か月350ドル、各社1日40ドル・1か月175ドル。更新時は、未選択の提供元も含めて設定済みの予算とモデルを引き継ぐ。確定記録 `data/.provider-settings-authority.json` には照合用のハッシュを保存する。旧版の復旧監視が入っているMacで保存形式を移行する手順は、[更新ガイド §3-A](../guides/UPGRADE_AGENT.md#3-a-提供元設定の保存形式が変わるときの復旧監視)を参照。

導入時の省略オプションは `config.json` の `install_args` から読む。移行前に限り `data/install_options.json` と照合する。記録がない・不正である状態と、省略なしの空配列を区別し、移行前の記録が競合する場合は再導入を停止する。

## 導入オプションの移行条件

設定への保存と既存の導入記録の読取りは、同じ選択を維持しなければならない。`install_options.save` は設定の編集ロックを取得し、読取り時の記録と公開直前の記録を照合して、設定ファイルを一括で置き換える。旧記録の移行では、移行中のreceiptが残っていれば停止する。再導入に必要な記録の欠損・不正・競合を空配列とみなさず、選択を確認できなければ停止する。更新処理が一時的に付けた修復用の省略オプションを、本人の選択として保存しない。

初期設定、任意機能、解析結果の採用設定、監視、辞書の切替えなど、`config.json` を更新する各経路は、並行した変更を失わない必要がある。承認記録・辞書・認証情報が先に保存される場合は、部分的な成功と設定保存の成否を区別する。実行中の旧writerや旧版への復旧で安全に扱えない状態は、切替えずに保持する。

移行を確定すると、検証済みの旧 `data/install_options.json` は `data/.install-options-pre-v3-*` の下に退避する。業務データ、配送・承認の記録、認証情報はそれぞれの保存先に残る。

## 検証条件

一時ディレクトリと架空の設定だけを使い、初回導入、中断後の再開、既存値の保持、更新・旧版への復旧を確認する。設定の並行保存、破損・欠損・未知の項目、読取上限、symlink、認証情報と承認記録の保持も検証する。未指定値は新しい版の既定値に追従し、明示値・`null`・空配列はそれぞれの意味を保つ。実サービスや実データには接続しない。
