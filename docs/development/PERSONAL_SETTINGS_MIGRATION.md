# 個人設定とHermes plugin設定の移行案

## 現状と目標

この文書は設計案であり、中央設定への移行や新しい権限readerは未実装である。現行のMCSは `config.json` の通知先設定と、Hermes profileのplugin設定を併用する。`mcs_setup.py init` はplugin設定をHermes CLIで保存し、認証情報は別の保存先で扱う。

固定SHAの [Hermes PluginContext.get_config](https://github.com/NousResearch/hermes-agent/blob/2c08ca7ade8f867d07e4bff6581be54405b0c9d0/hermes_cli/plugins.py) は、キーごとに `settings` を優先し、欠けたキーだけ旧 `config` を参照する。このソースの確認は、当該SDKが実行環境で稼働している証拠ではない。

目標は、MCSの設定値とprofile別のplugin権限を `config.json` に集約し、通知先・操作権限を一つの所有元で管理することだ。認証情報、Hermesのplugin有効化・capability設定、他pluginの設定は移行しない。既存profileの自動移行や本番環境への適用は行っていない。

導入時に選ばれた省略オプションは、現在 `data/install_options.json` に記録される。更新案内はこの記録を再導入に引き継ぐため、欠損・不正と省略なしの空配列を区別する。中央化には、旧版への復旧と設定の並行保存に対応する必要があり、まだ実装していない。

## 段階と失敗時の扱い

1. **互換ブリッジの準備**: 旧profileでは既存の `get_config` を使い、`settings` と旧 `config` の優先関係を維持する。中央設定を読む経路は、対象profile・所有者・設定の版と完全性を確認できる場合に限る。欠損、不正、未知の版、所有者不明の場合は中央権限を使わず保留する。旧設定へ無条件に戻して権限を復活させない。
2. **profileごとの切替**: 旧設定の実効値と出所を確認し、中央設定の候補を準備する。対象の旧workerと操作入口の停止、設定writerの排他、中央・旧設定の一致を確認してから、旧 `settings` と旧 `config` の対象キーを除き、中央設定を有効にする。他pluginの設定、同じpluginの対象外キー、認証情報は保持する。どちらかの旧キーだけを除くと、残った値がfallbackで再び有効になり得る。

切替の途中状態と対象世代は永続的に記録する。中断後は実際の中央設定とHermes設定を照合し、想定した状態から再開する。内容が食い違う、または停止・排他を証明できない場合は保留し、自動で上書きしない。配送中・結果不明の試行と、後から届く事実のreceiptは既存の経路で保持する。

## 既定値と認証情報

未指定項目は、その版の実行時の既定値を使う。既に保存された値は、過去の推奨値か本人の明示値かを推測して削除しない。ウィザードの推奨値と未指定時の実行値が異なる項目は、移行前に実際の値と変更の影響を確認する。既定値への追従は、外部送信・権限・人の承認を広げる許可にはならない。

APIキーやBotトークンは `config.json` の移行対象に含めない。既存のKeychain、profileの `.env`、各adapterの私有credential保存先を維持する。設定の比較・診断・テストには秘密値や実データを出さない。

## 旧profileとrollbackの前提

移行対象は、profileとadapterの所有者を確認できた範囲に限る。中央設定の保存先は本人所有の正規ファイルとし、他者が書き込める場合は保留する。設定を探す起点の信頼性と、既存の独自保存先との互換も確認する。未特定profileの不存在や、プロセスの停止を再起動要求だけから推定しない。中央権限を更新しても、既に起動したworkerが古い権限を保持する可能性があるため、権限変更の反映方法も確認する。

旧版へ戻す場合は操作入口とworkerを停止し、中央設定の現行世代から旧版が読む設定を再構築して照合する。途中で値が変わった場合や、旧版が同じ権限を読み取ることを確認できない場合は起動を保留する。再構築した旧設定は旧版運用時の一時的な投影とし、中央へ戻すときに再照合して除く。

Hermes設定の安全な一括比較・更新、他writerとの排他、固定SDKのprofile識別、停止と再起動の確認方法は未検証である。導入オプションを中央へ移す前には、初期設定、任意機能、監視、辞書の切替えなど、`config.json` を更新する各経路の競合と、承認記録・辞書・認証情報の部分的な保存も扱う必要がある。個別キーの書込みや再起動要求だけで、これらの条件を満たしたとは扱わない。

## 合成検証計画

一時ディレクトリと架空の設定・IDで、次を確認する。実サービスや実データには接続しない。

- `settings` と旧 `config` の混在、欠損・`null`・空配列、不正値、未知の版、管理設定、複数profileと所有者不明。
- `/mcs`、Discord・Slackの配送と操作で、利用者・channel・project・roleの許可範囲が移行前後で一致し、別profileを拒否すること。
- 初回導入、既存設定の更新、各書込み前後の中断、競合、復元、旧版rollbackと再開。対象外の設定・認証情報を保持し、不明な状態を保留すること。
- 稼働中の旧worker、権限変更、配送結果不明と遅延receiptで、既存の送信権と事実の記録を維持すること。

合成テストの後に、対象の固定SHAのHermes SDKを隔離環境で検証する。ローカルソースや合成テストの結果を、実稼働・実配送の確認とは扱わない。
