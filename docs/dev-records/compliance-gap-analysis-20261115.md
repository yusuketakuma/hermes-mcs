# hermes-mcs 医療情報システムとしての法令・ガイドライン対応 ギャップ分析（2026-11-15）

**法的助言ではありません。** 一次資料を読んで、要件と現在の実装の差を整理したものです。
導入・販売の判断は弁護士と、必要に応じて行政の窓口で確認してください。

## 結論

コードと文書で埋められる欠落のうち、優先度が高い2点（アクセスログと外部AI送信の施設確認）を実装し、
施設が整える文書（対応ガイド・運用管理規程・リスクアセスメント・患者向け文例）を追加した。
残る最大のリスクはコードでは解決できない次の3点で、**販売前に必ず解消が必要**。

1. **MCS の規約。** 確認できた最新の契約者規約（令和3年8月施行）第5条4項は、患者情報を「文書または電子媒体などその媒体の種類を問わず複製すること」と「外部へ持ち出すこと」を禁じている。hermes-mcs の中核（ローカル保存・Slack通知）がこれに当たり得る。運営会社（コラボスクエア）からの書面許諾が前提。現行規約は Web が JavaScript 描画で本文を取得できず、未確認。
2. **外国にある第三者への提供（個人情報保護法 第28条）。** Slack・Discord・Anthropic・OpenAI は米国の事業者で、米国は同等水準国ではない。要配慮個人情報（病歴等）を送るには、本人同意か、契約による基準適合体制（規則第16条）の整備が必要。どちらで行くか、契約書・同意書式は弁護士の確認事項。
3. **医療機器プログラム該当性。** 情報共有・閲覧の支援は非該当の典型例だが、`symptom_after_med_change`（薬の変更と症状の同時出現）を「副作用検知」と説明すると該当性が変わり得る。販売資料の表現を統制し、機能追加前に都道府県薬務課か PMDA に相談。

## 弁護士・行政・運営会社に確認すること

- コラボスクエアへの書面照会: 自動取得・ローカル複製・他社クラウドへの通知転送の可否、現行規約の本文。
- 弁護士: 第28条を同意で行くか体制整備（Anthropic・OpenAI・Slack の DPA で規則16条1号を満たすか）で行くか。同意書式と掲示文。販売者（Yusukeさん）が委託先になる場合の契約・再委託条項。漏えい時の報告体制。
- 都道府県薬務課または PMDA: 確認候補・緊急度の並べ替え・薬の変更と症状の候補が医療機器に当たらないことの確認（販売資料の表現を含む）。
- 販売者として: 提供事業者ガイドライン第2.0版のサービス仕様適合開示書、MDS/SDS の作成。

## 実装の範囲（PR）

- `mcs/core/access_log.py`: 記録・読取り・連鎖検査。
- `adapters/common/dispatch.py`: Hermes・独立 Slack/Discord・LINE WORKS 共通の入口で記録。
- `mcs/core/external_transfer.py`、`cloud_policy.resolve_settings`・`semantic_policy.runtime_config` の自動有効化条件、`mcs setup init` の新規作成時に確認待ちを記録。
- `mcs/ops/mcs_compliance.py`: status / acknowledge / access-log。
- 適用には Hermes gateway の再起動（LINE WORKS は独立アダプターの再起動）が必要。実機では未検証。
