# シグナル優先順位1–8 実装レビュー記録（技術要件のみ）

この文書は開発時の技術判断と修正内容を整理したものです。実データ由来の
識別子、投稿内容、個別の診療情報、集計実績、稼働設定値は含めていません。
過去の運用状態や現在の配備完了を示す証拠としては使用しません。

## 背景

同一投稿から複数の対象に関するシグナルが作られる場合、通知が重複して
見えることがある。配送の重複と別シグナルの生成を区別する必要がある。
また、行為を実施できないという記述を、実施済みの開始・中止へ変換しては
ならない。以下はこれらを含むシグナル改善の技術要件と判断記録である。

## 実装内容

| # | 要求 | 実装上の要点 |
|---|---|---|
| 1 | 自己投稿の抑制 | `GET /users/self` 由来の `self_profile_v1` と設定の明示オーバーライドから自己同一性を解決する。検知時に除外し、自己投稿を応答確認にも使用する |
| 2 | 薬剤師宛依頼の未応答候補 | `pharmacist_request_unanswered`。宛先判定、応答期間、検証状態、正式依頼登録、後続応答を確認する。通知は記録上の未確認を示す |
| 3 | 実施能力と薬剤変更の分離 | `MED_NOT_CAPABILITY_SQL` と `med_capability_evidence` をシグナル・統計で共有する。抽出でも能力・実施可否を開始や中止へ昇格させない |
| 4 | 他職種宛の処方関連依頼 | `rx_request_visibility`。薬剤師宛・宛先不明を除き、処方関連の依頼を参考情報として提示する |
| 5 | アドヒアランスの懸念 | `adherence_concern`。薬剤情報と本文の対応を確認し、懸念自体を否定する表現で誤発火しない |
| 6 | 応答確認の共有化 | `_self_post_exists` と `_request_registered` を応答系検知器で共有する。記録がないことを対応がなかった証明としない |
| 7 | 即時通知とまとめ通知 | `SIGNAL_TIERS`、`sig_units`、`med_group_key` を生成時と配送時で共有する。未送信のまとめ通知だけを結合し、緊急度は単独シグナルにせず通知の修飾に使う |
| 8 | 退院と症状の候補 | `discharge_notice` と `symptom_after_med_change`。前者は関連シグナルへ引き継ぎ、後者は同一投稿内の結合に限定する |

## 共有実装と判断

- 自己同一性は `_self_sets`、SQLでの自己投稿除外は `_self_author_pred`
  へ集約する。設定の明示的な空リストと未設定を区別する。
- 宛先は職種・施設を表す条件で照合し、作業内容中の単なる文字一致で
  薬剤師宛と推定しない。
- `med_group_key` と `sig_units` が通知の結合単位を決める。
  描画は単一・結合・まとめ通知で共通の処理を使用する。
- 未送信のまとめ通知は識別子を保持し、配送時に現在も有効なシグナル
  だけを解決する。全件が解決済みなら配送を終端させる。
- 既に配送を開始した通知の内容を変更しない。例外で一部検知が失敗した
  場合も、他の検知器を継続できるよう型単位で分離する。

## 修正記録

- 否定表現による誤発火を減らすため、通常の否定照合と、表現そのものが
  懸念を示す場合の照合を分離した。本文候補の事前絞込みも追加した。
- 緊急度は `extract_llm` と `extract_v1` の双方から確認する。
- 宛先判定を `PHARM_TARGET_SQL` へ集約し、依頼の可視化側も同じ条件で
  整合させた。
- 自己プロフィールの識別子を型検証する。プロフィールが存在する場合の
  空の職種集合も有効な値として扱う。
- アドヒアランスの薬剤経路では過去状態を除外する。
- 結合できない通知は先頭要素だけに縮めず、全要素を個別に描画する。
- プロジェクトを横断するまとめ通知も、配送時に要素ごとのアーカイブ
  状態を確認する。

## 古い未読通知の抑制

`notify_max_age_h` を設定した場合、期間外と確認できる投稿は原文を
取り込み、通知意図を作らず消費済みとして記録する。未設定時は従来の
通知動作を維持する。投稿日時が不明、または解析不能を示す値の場合は
古いと断定せず、通知対象に残す。

判定は `_filter_notify_age` で共有し、`save_patient`、`save_messages`、
`save_thread_replies` の全保存経路へ適用する。未読取得を通らない
`--jobs-only` でも同じ設定を渡す。既読化、抽出、シグナル評価の契約を
この通知抑制で変更しない。

## 不確実な配送と救出

送信未開始が証明できる保留通知について、有効なシグナルまたは対象投稿を
新しい通知へ救出する。部分送信の可能性がある場合は自動で再送しない。

対象はまとめ通知だけでなく、結合シグナル、単一シグナル、`new_messages`
にも及ぶ。保留と救出は同じ transaction で記録し、中断時に両方が配送可能な
状態として残らないようにする。`rescue_of` により救出を一度だけに制限する。

## 設定項目と限界

設定項目は `self_organizations`、`self_professions`、
`med_exclude_names`、`tiers`、`digest`、`digest_interval_h`、
`request_targets`、`notify_max_age_h`。本書は稼働中の値を記録しない。

- 記録上の未応答には、電話や訪問など別経路で対応済みの場合が含まれる。
- 宛先不明の依頼を薬剤師宛と推測しない。
- 同一投稿内の症状と薬剤変更の共起だけで因果関係を確定しない。
- 不確実な配送には照合が必要であり、exactly-once 配送を保証しない。
- 本書の整理に際してテスト、実データ照会、サービス操作、外部送信は
  実施していない。過去の実装記録を現在の検証成功として扱わない。
