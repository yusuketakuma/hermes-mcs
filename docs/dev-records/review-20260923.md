### 修復: probe_format が slot 決定の単一点を迂回

`local_llm.probe_format` が `extra_payload={"id_slot": BACKGROUND_SLOT}`
を直打ちしていた。第8ラウンドで「未pin probeがslot 2(RT)を汚染し得る」
を直すために pin した後、第10ラウンドで「全経路が request_slot() 経由の
一点決定」へ移行した際の取りこぼし。結果として `MCS_LLM_SLOT`・
`--slot`・`--lend-rt` のいずれも probe に効かず、文書化された
プロセス単位オーバーライド契約と矛盾していた。

修正:

- `probe_format(..., slot=None)` — `None` は `request_slot()` で解決
  (既定=BACKGROUND_SLOTで不変)、呼出し側の決定を明示的に渡せる形に。
- `extract_llm._probe_format` — `slot=_choose_slot(deadline=deadline)` を
  渡し、`--slot`/`--lend-rt` を含む抽出経路と同じ一点決定に統一。
  `--lend-rt` 時は /slots idle 確認が効くので安全側の性質は維持。

安全性: 既定挙動は不変(env・flag無しなら wire id_slot=0)。RT slot に
着地するのは operator が明示 opt-in した場合のみ — pin修復の意図
(無指定のprobeがRTに漏れない)は保持される。

回帰テスト(`tests/test_slot_routing.py` +4件):
`test_probe_format_honors_env_override`・`test_probe_format_explicit_slot_wins`・
`test_extract_probe_format_uses_choose_slot`・`test_probe_format_bad_slot_falls_back`
(不正なslot値はunpin扱いでRTに着地し得るため `request_slot()` へフォールバック)。
`test_local_llm.py` の pin 3テストに `delenv("MCS_LLM_SLOT")` を追加し、
既定値assertが環境変数に依存しないようにした(後者2件は request_slot()/
_choose_slot 経由で元々 env 依存だった衛生修正)。
