# hermes-mcs 全体レビューとローカル改善（2026-09-25）

## 対象と到達点

- 基準: `4c9b0c0`。開始時の追跡ファイル246件を領域別に分担し、本文・呼出し・契約を確認した。対象一覧は [coverage-20260925.json](coverage-20260925.json)。変更不要のファイルにも機械的な編集を加える方式は採っていない。
- 対象は hermes-mcs と Hermes の接続経路。Hermes 側は config CLI、Discord 入力、plugin command context と対応テスト・説明を確認した。Hermes 全体の監査ではない。
- コード・合成テスト・現行仕様・履歴資料を区別した。SVG は XML を通読し、変更した概要図と新規合成図案はローカル描画も確認した。
- MCS の実 ledger、認証ファイル、稼働設定は開いていない。実サービスへの接続・再起動・配備・push は実施対象にしていない。後述の既存テスト隔離不足を検出したため、「外部影響が一切なかった」とは断言しない。
- 途中で担当外から入った並行差分も保持し、現在の作業ツリーで統合検証した。この記録は全差分の作者を断定するものではない。

## 実装・統合した改善

| 領域 | 内容 |
|---|---|
| 収集 | WebSocket の宣言長を読込み前に制限し、control frame の上限を確認。handshake 失敗時に socket を閉じる。latest の不正な空値を成功扱いしない |
| 再取得 | 部分成功後の履歴カーソルを retry と一緒に保存。件数不足の thread を再取得し、legacy の NULL body state の返信も回復対象に含める。安全に取得できなかった self probe を抑止済みにしない |
| 実行記録 | 最後のコマンド取込の失敗も run の完了状態へ含める |
| 抽出 | 不正な明示年を別年へ補完せず、投稿年不明時の固定年推測を除去。ルール世代を更新。同一バッチ index の競合出力は既存の単体再試行へ戻す。thread context の同時刻境界も補正 |
| 閲覧・集約 | 非 object metadata を安全に扱う。期間外・予定の服薬期間を current とせず、日付境界で再集約する。snapshot 世代交代時に許可 project cache を更新する |
| 評価 | 正解ラベルと出力を一対一で照合。全件未評価、先行投稿の監査失敗、relation 失敗を合格にしない。shadow 評価の chunk size を抽出・修復へ渡す |
| LLM | 非ASCII数字による slot 解決例外を防ぎ、schema を無視した応答や length stop を schema 対応の証拠にしない |
| 配送 | 再取得した添付と古い別名ファイルの不一致を修正。重複した本文 chunk の個数を保持して再送を判定。Slack の後続結果を巡回し、先頭32件待ちによる飢餓を解消。接続先 workspace の native client を選ぶ |
| 権限・秘密 | 転送・復元・書換えされた Discord コマンドを本人の直接入力とみなさない。notification receipt の必須 scope の省略を拒否。Bot token を Hermes CLI の argv へ渡さず stdin 経由で保存 |
| ファイル保存 | export・統計参照値・backup を排他的に作成した一時ファイルで公開。export/参照値は0600。設定・秘密の更新も既存の原子的保存を利用し、失敗時に前の内容を保持 |
| 更新・復旧 | manifest の保持、rollback 履歴と結果の記録、durable な記録後の gateway restart 判定、flock 失敗時の fd 回収を修正。Git 状態の取得失敗を clean としない。更新差分との名前一致だけで未追跡ファイルを追加削除する処理を廃止 |
| DB検証 | 復旧候補の対応schema世代・必須列を検査し、中断migration表と既存移行が拒否する重複を除外。旧attachments/read_marks形式の移行と合成レコード保持を確認 |
| CI・説明 | 正当な設定処理と禁止された直接API処理を分離して静的検査。複数行 SQLite URI と writer の呼出し経路を確認。shellcheck 違反、旧モジュールパス、送信範囲・QC・配備候補の説明を修正 |

削除した内部処理には、置換された危険なファイル削除関数、未使用の薬剤集合、空の stats 分岐が含まれる。呼出しと既存の挙動を確認して整理し、履歴 migration や実データは削除していない。

## 未完了・制約

### 配布版 Hermes との組合せ

新しい `config set --stdin` と native command provenance は隣接 Hermes のローカル差分。
配布/CI の固定commitにはこの未コミット変更を含められない。
Hermes側の変更を公開した後、`install.sh` と CI の pin を同じ検証済みcommitへ
更新し、固定版のCIを再実施する必要がある。未公開SHAを作ったり、チェックをskipする
変更はしていない。今回の成功はローカル両repositoryを組み合わせた検証結果である。

### 既存テストの外部操作経路

初回全体テスト後、既存 recovery fixture に実 `launchctl bootout` と通知用
Hermes subprocess へ到達し得る箇所を発見した。bootout対象は合成labelだったが、
HOME の隔離だけでは launchd の操作を防げない。fixture を明示stub化した。
初回実行による通知の成否やサービス影響は未確認で、実資産の照会は追加していない。
それ以降の該当回帰はサービス呼出しをstub化して実施した。

### 保存済み実例を含む文書

`signal-priorities-20260924.md` と `phase-j-record.md` §6 に実データ由来と記載された
個別情報があり、`docs/screenshots/discord-notify.svg` も匿名化例と記載されている。
値や原文はこの報告へ転記しない。技術要件のみの一般化案と完全合成SVG案を用意した。
保存済み記録の削除にあたるため、`data-loss-gate` の確認待ちで原本は保持している。

- 案: `/tmp/mcs-phase-j-section6-sanitized.md`

この3対象を修正しても過去の Git 履歴からは除去されない。履歴書換え・公開済み複製の
削除・実データ操作は今回の範囲に含めていない。

全ファイルの読了やテスト成功は、欠陥が皆無であることや全入力に対する安全性の証明ではない。
