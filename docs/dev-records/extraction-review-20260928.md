# 未プッシュ9コミットの抽出レビュー対応

対象: 8f80165〜d7eab03。実装はローカルのみ、実データ・外部API・実LLMは未使用。

- thin再抽出は実artifact IDと患者・本文hashを照合する。失敗は旧結果を保持して一度で終了する。
- 修復は既存の臨床項目とhigh分類を保持する候補だけを採用する。QCによる明示的な訂正は独立の経路を維持する。
- thin判定は要約のキー数を除外し、臨床項目数を使う。既存thinの再抽出にno-signalフィルタを適用しない。
- 表示は選択されたLLM結果を優先し、ルールの別主体・別時点の値や除外イベントを混ぜない。LLMがない場合のルール表示と添付参照は維持する。
- 死亡の活用形、外来、口語の訪問表現をイベント語彙に追加する。語彙検証は意味理解の完全な代替ではない。
- QCはバイタルから各領域を順番に監査し、重複イベントで予算を消費しない。既存の項目別checked/total/uncheckedを維持する。
- 抽出対象と残件・監視の判定を共有する。ジョブ監視は設定対象・実行予定・最新進捗を考慮し、正常な新規待機を停止扱いしない。
- single推論の開始最低残時間を75秒にし、90秒のtick枠で準備時間を確保する。既存コメントの最大69秒に余裕を加えた暫定値であり、今回の実モデル計測値ではない。
- 通知のsource fingerprintは選択されたfact/rule artifact世代を含め、訂正前の書込みtokenを失効させる。
- 合成ベンチに否定・口語・家族・複数測定を追加。バイタルと症状の主体・時制を採点し、ケース別呼出数・修復数・token/時間、全体p50/p95とコーパスhashを保存する。異なるコーパスの比較は拒否する。

再現テスト: `test_extract_review_regressions.py`、`test_structured_review_regressions.py`、`test_notify_review_regressions.py` と既存QC/監視/評価器テスト。

実モデル比較は未実施。評価器にbefore/afterの同じコーパスの結果を入力できる状態まで実装した。実推論・本番適用・pushは別途の明示範囲。

## リファクタリング追記

上記の未コミット修正を保持した状態から、次の重複・責務の混在を整理した。

- 再抽出元の照合SQLを共通化し、臨床項目の対象フィールドと閾値を一箇所で定義。未使用になったキー数評価を削除。
- QCの監査項目選択と設問生成を分離。項目順序、元配列のindex、数値の設問ID、監査上限を維持。
- キュー監視をジョブ待機・抽出残件・解析段階の出力不足に分離。読み取り専用接続を確実に閉じ、途中で読めなくなっても先行する警告を保持。
- 表示の対象artifact種別を共通定数へ統一し、ルール候補を追加する条件を明示。
- ベンチの入力とhashを同じ読取りから作成し、時間分位点の算出を独立させた。再抽出テストの一時DBはfixtureで閉じる。

患者ID省略の旧形式、QCの重複除去後のindex、監視途中のエラー、分位点の境界を追加検証する。抽出・表示・QCの仕様、DB形式、外部操作の承認範囲は変更していない。
