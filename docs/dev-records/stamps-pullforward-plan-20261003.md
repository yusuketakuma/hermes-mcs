# MCSスタンプ計画の1.0.11前倒しと追加案（2026-10-03）

オーナー指示（2026-10-03）: スタンプ関連ロードマップ（[stamps](../roadmap/stamps.md)）の
1.0.12・1.0.13項目を1.0.11へ前倒し実装し、既存計画と追加案の計画を策定する。
本書は計画と実装範囲の記録であり、実API・実画面での検証完了を宣言しない。
[ROADMAP §5](../ROADMAP.md#5-版計画)の「前の版のshadow照合と判断事項が揃ってから次へ進む」は、
今回の指示により**有効化の順序**の規定として扱い、コードの実装は先行する。

## 1. 共通方針

- 前倒しした機能はすべて既定offの設定ゲートを持つ。有効化条件（22-Aの未読保持、#22-D2/D3/D5、#23-D1、#24-D1）は正本のまま。
- schemaは8のまま。新しい表は`CREATE TABLE IF NOT EXISTS`の加法追加とし、`SCHEMA_VERSION`を上げない（更新判定`schema_bump:7->8`を変えない）。
- 新しいGETは既存`_request`経路（no-redirect/no-proxy、`no_extend_session`）に限り、POST・既読化の新経路は作らない。
- 新しい取得はsemanticの後、`_run_metadata_shadow`の予算（最大25秒・余白30秒）の内側で動く。本文hash・coverage・新着通知・抽出に触れない。
- スタンプで割当・承認・業務完了・依頼台帳を自動変更しない。「記録が見つからない≠対応がなかった」を集計にも適用する。

## 5. 表示グループの設計

自分の投稿への反応表示、#25の併記と一覧、#23の表示、追加案2・3は、
最初の実装担当の起動が自動判定で拒否された。ユーザーの再指示で実装する。設計は次のとおり。

- 自分の投稿は種別ごとに本人分を除いた他者件数（2026-10-03以降は`message_metadata.stamp_line`の絵文字表示）。count 0種別を0で補わない。
- カード脚注: 本人の投稿（送信者ID判定）なら他者反応、それ以外は既存の本人反応。
- digest: 「反応が観測されていない自分の投稿」（`metadata_refresh_publish`がtrueのときだけ）、「自分宛で応答未観測」（未対応の依頼候補シグナルと本人宛メンション。self ID不明なら出さない）、取得状況にスタンプ未取得・取得不正の件数。
- 患者サマリー: 依頼候補の返信状況（`reply_state`、loop候補の有無）。
- 閲覧CLI: メンション・しおり・ピン留めの有無と未取得。
- 未確認一覧: 見出しに本人反応ありの件数（確認状態は変えない）。
